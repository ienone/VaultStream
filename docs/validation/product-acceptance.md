# 产品级验收指南

> 目的：把“测试是否真实可用”从单元测试结果拆成可执行的产品验收步骤。单元测试证明代码路径，产品验收证明当前部署、配置、账号和外部平台链路能工作。

## 自动冒烟检查

后端启动后运行：

```powershell
python scripts/product_smoke_check.py --base-url http://127.0.0.1:8000 --api-token <你的 API_TOKEN>
```

也可以通过环境变量传入：

```powershell
$env:VAULTSTREAM_BASE_URL="http://127.0.0.1:8000"
$env:VAULTSTREAM_API_TOKEN="<你的 API_TOKEN>"
python scripts/product_smoke_check.py
```

脚本只读取状态，不创建内容，不调用真实外部平台。它会检查：

- 后端健康状态。
- 初始化状态。
- 平台账号健康汇总。
- AI 能力状态。
- 收藏同步状态与最近运行记录。
- 后台任务诊断。
- 语义索引状态。
- 发现源列表。
- 分发队列统计。

结果中的 `ok=false` 表示控制面或鉴权不可用，应先修复本地部署、API token 或后端任务状态。结果中的某项 `summary` 只表示“控制面可见”，不代表真实平台解析、真实 LLM 调用或真实推送已经成功。

## 人工端到端验收

以下步骤需要真实账号、真实网络和真实配置。每次发布前不一定都全跑，但做功能判断时应至少覆盖相关链路。

1. 普通 URL 入库
   - 添加一个公开普通 URL。
   - 验证收藏库出现新内容。
   - 验证解析状态成功，标题、正文、封面或媒体字段符合预期。

2. 平台登录态解析
   - 添加知乎或小红书 URL。
   - 登录态有效时应成功解析。
   - 登录态失效时 UI 应显示可理解的账号/风控/403 类错误，而不是裸异常。

3. 发现源同步
   - 配置 RSS 或 Telegram Channel 发现源。
   - 手动触发同步。
   - 验证发现列表出现新条目，并记录 `run_id` 或最近同步时间。

4. 收藏同步
   - 在自动化设置中启用至少一个平台。
   - 手动触发同步。
   - 验证最近运行记录中有本次 `run_id`、状态、导入数量、跳过数量和失败原因。
   - 失败任务应可以查看详情；可重试的失败任务应能重新触发。

5. 语义搜索与摘要
   - 配置摘要模型和 Embedding。
   - 添加或重建一批内容。
   - 验证 AI 能力状态从不可用/待索引变为可用。
   - 在收藏库中执行语义搜索，确认结果包含分数、匹配来源和可读摘要。

6. 分发队列
   - 配置一个 Bot 目标、分发规则和目标绑定。
   - 让一条内容进入队列。
   - 在审核队列中只操作一条 `queue_item`，确认不会影响同内容的其他目标队列项。
   - 失败记录重推时确认只影响对应 `target_id`。

7. 推送
   - 对一条队列项执行立即推送。
   - 验证目标端收到消息。
   - 验证后台任务诊断记录本次推送 `run_id`、目标和结果。

8. 故障可理解性
   - 故意填错 LLM key、断开平台登录或禁用推送目标。
   - 验证 UI 能指出具体失败类别和下一步操作。

## 结论口径

- 后端非 integration 测试通过：只能说明本地核心逻辑稳定。
- integration 测试通过：说明特定真实平台链路在当时环境可用，但可能受平台风控、网络和账号状态影响。
- `product_smoke_check.py` 通过：说明本地后端控制面、鉴权和状态汇总可用。
- 人工端到端验收通过：才可以说对应用户功能在当前部署中真实可用。
