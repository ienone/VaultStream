# 2026-04 架构审计摘要

> 来源：旧 `architecture_audit_2026-04-07/` 目录。  
> 当前状态：历史参考，不代表当前实现状态。

## 审计关注点

旧架构审计覆盖了系统模块图、核心数据流、架构异味、前端状态管理、RAG/向量检索和重构路线。它的主要价值是说明 VaultStream 曾经从“功能快速堆叠”向“服务边界收敛”转变时暴露的问题。

## 历史主要发现

- 内容入库、解析、摘要、Embedding、Discovery、分发等链路曾分散在多个任务和服务中，容易出现后处理顺序不一致。
- 配置读取曾分散在环境变量、全局 settings、DB settings、运行时缓存之间，容易出现 UI 修改后后台任务不生效。
- EventBus、后台任务状态和长生命周期对象存在类级状态、资源释放和多实例边界问题。
- 前端存在大 Stateful widget、Provider 生命周期、SSE 双路监听、错误吞掉、路由守卫加载态等问题。
- RAG/语义搜索早期方案过于依赖 JSON 向量和应用层计算，需要用阈值触发向量索引试点。

## 仍有参考价值的历史建议

- 优先让 ingest 后处理汇聚到单一服务边界，而不是在各入口重复调用 summary、embedding、distribution。
- 将配置读取收敛到明确服务，减少环境变量、DB setting、缓存和全局对象之间的漂移。
- 对后台任务建立可观察的运行记录，而不仅是日志或健康状态。
- 前端拆分应围绕状态所有权和交互边界，不只是按视觉区块拆文件。
