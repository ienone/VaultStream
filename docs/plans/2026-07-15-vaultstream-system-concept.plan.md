## 1. 产品承诺：可靠保留，持续理解，在需要时有用

VaultStream 是自托管的个人知识流系统。它接住用户主动分享的内容，也从用户授权的来源持续接收信息；把材料变成可读、可找、可引用的存档；围绕用户关注的问题持续整理变化，并在适当时机帮助判断与行动。

用户使用它，不应是为了得到一个需要不断维护的抓取后台，而是为了：

- 当下没空处理的材料不会丢，以后能找到并读懂。
- 不用逐个平台重复搬运收藏，也不反复读同一资讯。
- 已关注的事件能持续得到新证据、更正与分歧，而不是重复的全文摘要。
- 有问题时能沿真实来源检索、比较和回答，知道哪些仍不确定。
- 有价值的结果按自己的节奏到达，只有必要决定要求本人操作。

捕获 → 归档 → 理解 → 发现变化 → 行动是系统协作闭环，不是五个页面，也不是强制经过每个阶段的流水线。单条书签可以只保存；PDF 可先读原件再提取；无模型时仍能接入来源、阅读和全文查找。

## 2. 不变原则

1. **用户意图优先**：保存、阅读、关注、通知和外发是不同选择；不以后台状态代替用户意图。
2. **证据先于生成**：结论回到原文、页码、消息或时间点；综合稿不成为证明自己的来源。
3. **持续能力以结果衡量**：周期运行、开关、队列和成功响应只是机制；减少重复操作并持续产生有效结果才叫自动化。
4. **确定性流程管边界，模型管语义**：身份、权限、游标、版本、保留、重试、发送由规则执行；模型解释给定材料，Agent 处理开放式任务。
5. **可修正且能继续**：用户修正不能被覆盖，也不能因一个局部修正让整个目标永远停止更新。
6. **成本和隐私显式**：未经授权不把私人资料、账号或附件交给模型/外部目标；小任务不用无界 Agent 探索。
7. **派生状态可追溯**：保存不等于解析完成，解析不等于理解正确，生成不等于索引或外发成功。

## 3. 产品对象的关系

| 对象 | 定义 | 不应混同 |
| --- | --- | --- |
| 内容 | 一份具有稳定身份、当前可读表示与媒体的材料 | 一个抓取任务、一条通知或一篇万能帖子 |
| 来源记录 | 材料从哪里、何时、因何种分享/同步/转发进入，以及必要上下文 | 单一平台标签；去重后不能全部丢弃 |
| 持续来源 | RSS、频道、平台收藏范围等输入配置 | 平台账号或输出目标 |
| 平台账号 | 访问身份与凭据、实际能力和失效修复 | VaultStream 访问密钥、Bot 身份 |
| 保存意图 | 用户希望长期拥有材料 | 候选暂存、事件证据保留、未读状态 |
| 事件 | 围绕同一具体事件/问题的材料、关系、变化和解释 | 任意同主题材料、生成文章模板 |
| 关注 | 用户要求持续观察的对象与问题、范围和通知意图 | `active` 事件状态或关注一个平台作者 |
| 综合/简报 | 从特定版本材料形成的解释或阶段结果 | 原始证据、每次运行日志 |
| 自动任务 | 以持续目标为中心的配置与执行关系 | 通用 DAG 图、一次 run |
| 消息 | 需要注意/确认或用户请求的回执 | 所有资讯、所有 Bot 聊天和所有后台进度 |

来源和账号在界面上合并为一个工作区，在模型中保持独立。一个账号可以供多个读取能力使用；公共来源不需要账号；一个 TG chat 可输入也可输出，但授权分别存在。人物、主题首先来自可导航字段，只有真实关系任务需要时才引入独立实体。

## 4. 信息捕获与持续接入

### 主动保存

统一承接应用内粘贴/上传、Android 系统分享、Telegram/QQ Bot 及后续桌面快捷入口/浏览器扩展。链接、文字、文件、多个附件、转发评论与接收上下文进入同一保存不变量，入口体验可以不同。

先可靠接收，再做可选丰富。明确保存指令可按既定策略执行；“第二张图做封面”“补充到上周事件”“只留文字和关键图”“加入通勤队列”等需要模型时，使用受限上下文和可撤销动作。模板、合并对象、外部发送或大媒体成本不确定时只问一个必要问题。不把严格前缀匹配称为自然语言理解。

### 持续接入

优先稳定 RSS/公开接口、用户授权的平台收藏和频道；网页传输也是 Adapter 可选的明确机制，不强迫所有平台拥有同一种接口。支持能力必须声明收藏范围、集合信息、分页与登录方式，不根据平台名称猜“都能同步”。

持续同步需要首次导入、增量、定期覆盖检查、会话失效恢复及来源变动处理。平台游标/offset 只能证明该接口的分页位置；上游重排或缺失快照时明确限制，用头部重扫与幂等合并降低遗漏。外部取消收藏默认不删除本地存档，不承诺双向同步。

仅在稳定接口/页面读取不能完成具体目标时，才引入有范围、预算、停止条件和授权的 Browser Agent。已有登录浏览器或网页请求客户端不等于主动探索已完成。

## 5. 内容、版本与保留

不强迫所有材料拆成互不相通的三层表，但必须分清：来源证据、当前可读内容、可重建智能结果。正文、字幕、页码可以同时服务阅读与搜索；生成结果被用户采用后仍保留来源性质与修订关系。

- 平台身份/规范化链接用于精确去重，来源正文/媒体特征用于后续近似判断；新评论、集合与转发语境作为来源保留，不因去重而丢弃。
- 原网页 HTML 可按成本和来源易失性短期或长期保留；可读正文与关键证据优先。视频/音频可仅保留元数据、字幕和封面，原媒体归档由明确策略决定。
- PDF 等用户上传原文件应可靠保存；扫描无文本可以先读原页，不冒充 OCR。内容删除、缓存清理、候选到期和不可逆擦除是不同操作。
- 用户修改过的字段保持保护；重新解析产生可比较候选，不静默覆盖。引用应逐步绑定稳定来源版本及片段，旧结论不能悄悄指向已改变的新正文。
- 候选到期只清理未采纳且无依赖的内容。事件证据、用户保存或已发送结果引用的材料不能被 TTL 独立删除；证据保留不等于自动加入用户默认资料列表。
- 用户明确要求擦除时说明对引用与结论的影响并标记失效，不为了“证据完整”偷偷保留其要求删除的秘密副本。

需要完整备份/恢复路径：数据库、媒体、可重建索引及凭据密钥分开说明；恢复到空环境后能阅读和定位证据才算成功。不能只提供下载数据库按钮。

## 6. 消费模板与跨页面会话

模板以主要消费方式决定，不以平台强制绑定。保留文章、图文笔记、短帖子、帖子串、图集、对话/消息包、视频、音频/播客、文档与书签的不同语义；不把串与聊天拼成没有节点来源的长正文，也不把播客当普通附件。

每类能力都包含生产与消费两端：Adapter/提取器输出真实结构和覆盖状态，阅读器保留层级与定位，检索能返回合适粒度的证据。拥有枚举和演示模板不等于能力完成。首批优先保证已有高频文章、社交图文、视频、文档闭环；串/消息包和通用 OCR/ASR 随真实需求成套推进。

音视频共享一个应用级播放会话：详情、mini player、队列、书签、逐字稿与系统控制延续同一身份/进度。离开详情不重建播放器；打开其他媒体不静默抢播；关闭与收起语义不同。Android 后台媒体、锁屏/耳机控制和 PiP 属于完整体验，其他平台按实际系统能力接入。短媒体/模拟器成功不替代真机长播放和中断恢复。

文档共享文件/页码状态，原页预览与提取文本可以切换。文章、表格、代码、图集的布局随空间调整，但阅读位置与对象不能因断点变化丢失。细节由[前端模板规范](2026-06-10-frontend-information-architecture-redesign.plan.md)负责。

## 7. 搜索、问答与知识使用

统一搜索结合精确字段、全文、语义与范围过滤，先返回材料与命中片段。用户可沿来源集合、标签、事件或引用继续查找，再显式调用 Agent 比较或回答，不用聊天答案取代搜索。

证据粒度随模板变化：文章段落、串/聊天节点、媒体章节/时间区间、文档文件/页码。结果必须说明原文、平台 AI 字幕、OCR 或模型解释的性质；多文档引用不丢文件身份。模型没有依据时拒绝补全，top-k 非空不是可回答条件。

检索演进先验证召回覆盖、权限、版本与无答案行为，再决定重排/索引技术。不得把只扫描有限近期向量的实现描述为全库搜索；何时需要专门向量引擎，应由真实数据规模和旧材料漏召回验证决定，不预设换数据库即可解决 RAG。

长期偏好来自显式范围、用户修正和可引用材料，不把历史聊天无限注入，也不把模型以前说的话变成知识事实。

## 8. 关注、聚合与有效变化

主动接收的目标是减少重复阅读并保住重要变化，而非抓得更多。确定性去重和来源归属先行，检索候选旧事件/证据，其后模型判断同一事件、互补信息、观点分歧与新颖性；相同主题不等于同一事件。

事件包含标题/范围、观察问题、成员及角色、版本化综合、关键变化和必要的人工决策。关注描述用户希望继续观察什么；事件可存在而未被关注，取消关注也不等于删除事件。

持续聚合需要：

1. 识别新增、修订、撤回和新增评论，而不是仅按抓取时间重跑。
2. 找回相关历史材料，不把“最近几条”当相关性检索。
3. 输出可为空：无实质变化不生成新报告或提醒。
4. 逐条引用输入版本；有效引句不等于逻辑蕴含，生成内容保持未核实标识。
5. 用户锁定某个关系/结论后仍可接收新的独立建议，不冻结整个事件。
6. 综合保存、证据保留、索引和可选送达形成耐久交接；局部成功可独立恢复。

动态主要承载“变化”，事件详情承载完整材料与综合。单条内容摘要、事件综合、关注简报和后台活动摘要必须分别命名；默认不把四者对同一批材料重复通知。

## 9. 自动化与 Agent 的共同边界

自动化是系统能够持续完成事情的能力，首先做通持续收藏同步、事件变化整理、定期有证据简报。用户配置的是目标、范围、节奏和输出；内部执行阶段可诊断，但不是使用前必须掌握的知识。

确定性执行器负责权限、采集、幂等、版本、租约/恢复、成本限制和外部发送。模型执行有界摘要、分类、关系/变化判断；Agent 适合用户表达意图、比较材料、寻找缺失证据、解释失败及形成规则草案。不要让 Agent 替代每次轮询、每条去重或每次重试。

Agent 在分享、资料、事件和自动任务中带着上下文进入同一会话。只读可顺畅进行；写操作、高成本与外部发送遵守持久确认和策略，过期会话、账号退出或暂停后的迟到结果不能获得旧授权。普通工具过程轻量，证据与结果突出。

首期不引入通用可视化工作流平台。用已有任务/队列实现明确步骤、输入版本、结果复用、有界重试、暂停和人工介入；只有实际出现无法表达的多阶段用户任务时，才扩展编排能力。一次 run 记录是结果与审计，不等于执行能自动恢复。

## 10. 通知、推送与发送未知

保存不等于外发，生成也不等于外发。分发依据范围、规则、审批、目标状态与静默策略独立执行，用户可预览并暂停。

消息区分需要确认/修复、重要关注变化、主动任务回执与静默活动；连续同一失效去重，无变化不打扰。Bot 的普通对话不必全部复制进消息盒子，但由其发起的捕获、Agent 确认和结果能回到同一对象。

外部发送有独立尝试记录。远端接受与本地提交不能组成单个数据库事务；无平台幂等/查询契约时不承诺 exactly-once。区分未发送、明确失败与结果未知，后者先核对，不盲目重发。运行页不能以生成成功掩盖尚未送达。

## 11. 模型调用、隐私与成本

建立小而明确的模型调用门面，复用供应商 SDK，不创建另一通用 Agent 框架。角色配置显示有效模型和数据去向，不采用 Agent → Text → Vision 的隐式猜测式回退。未配置、调用失败、预算不足和结果不合格分别表达。

- 确定性提取/规范化先于模型；相同输入版本和模型/schema 复用已有结果。
- 先去重归组再总结短讯，事件只处理受影响变化；长内容按需取原文和片段，不反复发送全库。
- 记录场景、输入范围/版本、模型、真实 usage、耗时、错误、复用与供应商缓存信息；缺字段记未知，不把本地缓存当 Prompt Cache 命中。
- 稳定系统提示、工具定义与策略前置，变化材料后置；能否命中供应商缓存用实际返回值验证。
- 日常界面不摆 token 仪表盘；设置与运行详情提供费用/延迟/重复调用诊断和可理解限额。
- 私密来源可禁止发往远端模型；新自动任务启用时明确发送内容和附件的范围，高成本行为单独确认。

## 12. 账号安全与模块化后端

近期保持单人自托管、FastAPI/Python 模块化单体和现有 SQLite 架构。账号、模型、内容与任务边界可扩展，不为了未来多租户提前重做整个系统。

平台 session/transport 负责请求协议，Adapter 负责解析或分页产出；账号 service 负责唯一凭据持久化、条件刷新与撤销，业务 service 编排用户任务，repository 保持短事务与数据不变量。调度器只产生 due 工作，执行器不在持有写事务时等待长网络/模型调用。Agent 工具与 HTTP 入口复用同一业务和策略。

凭据必须有明确静态加密与密钥生命周期设计，不进入模型、普通日志或配置导出。设计目标不等于现状已加密；当前差距见[架构分析](2026-09-14-product-architecture-review.plan.md#backend)。变更密钥/存储 schema 前确认部署、轮换、备份和丢失恢复方案。

内容写入与待处理工作应同事务交接；内容、来源、事件和媒体统一身份与保留约束。保留解析任务、运行结果与外部分发的不同语义，不把所有状态压进一个万能 Task，也不多建相互竞争的状态真相。

Rust、独立向量引擎或服务拆分只在真实负载证明值得时实验。选一个稳定边界比较资源、延迟与维护成本，验证收益后替换旧路径；平台私有协议、二维码和安全门禁不能因代码复杂就删除。兼容补丁必须有具体外部依赖证据、验证方式与退出条件。

## 13. 界面是结果入口，不是后端组织图

建议主导航：**动态**看现在的内容与变化，**资料库**查找和消费已保留材料，**关注**持续跟进事件。**来源与账号、自动任务**是明确的二级工作区；搜索、保存、Agent、消息、设置与播放会话贯穿上下文。

这替代旧“动态/收藏库/自动化必须始终同级”的目标，不宣称当前代码已经迁移。关注需要与增量结果一起上线，不能先放一个新标签；资料库保留现有内容地址，不为用户名称改变毁掉历史引用。

Material 3 Expressive 用于表达对象、层级、状态与连续性，而非大量圆角/指标卡。手机竖屏和正常桌面优先，其他空间按任务风险验证。同一语义状态改变布局容器，不丢草稿、阅读/播放位置。Animeko 借鉴的是探索—收藏—消费与自动选择/局部覆盖的组织逻辑，不照搬缓存主入口或把证据来源当可替换视频源。

## 14. 实施与判断标准

按[整体方案的依赖顺序](2026-09-14-product-architecture-review.plan.md#sequence)推进：证据与恢复 → 连接到可读结果 → 持续关注和新导航 → 搜索/Agent 使用材料 → 目标简报与送达 → 其他生产/消费能力。它是建议顺序，不授权一次性全量实现或无监督长期推进。

每个切片一起处理必要的前端、后端、数据与文档，先验证可演示的用户路径，再深化。需要 schema、公开协议、依赖或破坏性变更时单独确认；不因本文是蓝图就绕过迁移审批。实际执行才记录 process，不为概念方案制造进度。

理想状态不是功能数量，而是以下结果：

- 分享后材料不丢，来源和附件可读，失败可恢复。
- 持续接入不依赖人工搬运，重复与重排不会无声掩盖覆盖缺口。
- 关注更新提供新事实/分歧与原证据，无变化安静，纠正后能继续工作。
- 搜索/Agent 能找回旧材料，引用对应版本/页/时间点，没有依据时不编造。
- 运行中断、账号变化、来源撤回和发送未知有正确归类与后续动作。
- 备份恢复后资料仍能使用；清理不会留下失去证据却看似可信的综合结论。
- 手机与桌面入口清楚、阅读连续，不要求理解后台实现概念。

仍需实施时确认的产品参数：首次同步范围与覆盖提示、不同来源的保留成本、事件合并/通知保守程度、模型隐私与预算、通用 ASR/OCR 的真实需求、密钥备份恢复方式。它们不阻止本轮形成可继续实施的结构方案，也不应被硬编码为未经确认的永久默认值。
