# 模型调用降本提速与 Jev 评估

## 目标

用项目实际调用链、DeepSeek 历史账单和固定样本对照实验，判断哪些流程应保留代码判断、优化现有模型调用或引入 Jev，并实施收益明确的最小改造。

## 范围与顺序

1. 核对统计时间、API key、模型、输入/输出和缓存口径，区分账单事实与无法归因的调用。
2. 建立当前调用基线，检查调用合并、结果复用、处理顺序、输入长度、并发、推理参数和上下文选择。
3. 比较当前流程、优化现有流程、优化后加 Jev。关键计时至少三次，固定中文正常与边界样本，用留出样本检查误忽略、误归组和证据丢失。
4. 按收益决定是否修改分类/评分、聚合、检索、解析、切片、简报和 Agent。候选范围不等于每项都必须接入模型。
5. 完成本地入口及真实模型验证，记录质量、耗时、token、缓存、成本、采用决定和证据边界。

## 边界

- 保留当前未提交改动；默认不提交、推送、部署，不真实对外发送消息。
- 不改变内容保留、人工编辑、外部发送和授权策略；不以模型判断替代安全控制。
- 复用当前服务，不创建通用智能路由框架、兼容双路径或长期测试设施。
- 临时验证脚本只用于本次验收；私有原始账单仅在忽略目录保存；模型凭据只在进程内存中使用，不写入文件或 Git。
- 用户已手动重置 Codex 额度；禁止使用任何重置卡。

## 完成标准

主要开销有证据解释；非 Jev 优化有实测；主要 Jev 候选有采用/不采用依据；选定改造通过本地验收。受外部访问限制的部分明确记录，不以推测或替身结果冒充实际验证。
