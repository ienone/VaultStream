## 大块重构取舍

### 1. RSS 发现与收藏复用同一解析实现：优先推进

当前 `adapters/discovery/rss.py` 和 `adapters/rss.py` 都维护 RSS/Atom 正文、日期、图片、BBCode、原始 XML 内容处理。旧分支把前者变为调用 `RssAdapter.parse_channel` 的映射层，这个方向有实际去重价值。

不能原样搬入：旧发现调用传 `limit=None`，当前 `parse_channel` 却执行 `limit <= 0`；当前收藏侧抓取异常返回空列表，而发现侧已经要求失败传播、保留游标，并避免日志暴露私有订阅 URL。旧映射也没有保留当前 `raw_metadata.feed_url/entry_id`。

实施边界：统一解析与抓取契约，明确“有效空订阅”和“抓取失败”，保留原始条目身份、游标、分类标签及来源信息。不要另写第三套 RSS 解析器，也不要以重复实现充当兼容层。

验收：同份 RSS/Atom 输入经两个入口得到一致正文/媒体/日期；覆盖相对图片、CDATA、BBCode、超过默认条数、旧游标、HTTP 失败及私有订阅错误脱敏。先用临时样本核对，再验收已有来源，不保留一套长期测试设施。

### 2. Agent 改为原生工具循环：用户明确暂缓，本轮不实施

当前 `services/agent/service.py` 为 1,277 行，旧版 858 行。当前调用 `create_react_agent`，再包装 `StructuredTool`；工具最终共享数据库会话，并通过锁串行执行。一个有限步数的顺序工具循环能去掉图编排与包装层，模型仍负责选择工具，代码仍负责执行。

保留当前注册表、参数校验、执行器、持久消息与工具结果、停止行为、权限及确认；原生循环替换的是编排，不另建第二套 Agent。优先使用已有 `openai` 异步 SDK，不照搬旧分支的手写 HTTP 客户端。

旧版不能直接采用的原因：

- 历史上下文仅回放 user/assistant，遗漏当前已经保存的工具调用与结果。
- 当前确认通过数据库条件更新原子领取 pending 状态，并检查运行状态、会话删除；旧实现没有同等的领取保护。
- 不能遗漏 QQ 的材料引用、显式保存要求、真实入库结果核对及当前读取/诊断工具。
- 旧模型工厂仍有文字/视觉配置回退，不符合已统一通用模型的方向；当前 provider 参数也必须传递。

验收重点：多工具顺序执行、重复确认只执行一次、停止后不继续产生副作用、“保存第二个链接”的准确引用、普通聊天不保存、模型错误保留真实诊断。原生循环首先能移除 LangGraph；其余模块仍使用 LangChain，不能宣称一次删除全部依赖或必然降低 token。

### 3. 通用解析合并模型调用：高价值，但重写旧方案

当前 `content_agent.py` 947 行，旧版 465 行。当前已经存在明确语义 HTML 的零模型路径；复杂页还会调用结构扫描、字段提取，部分页面另有定位调用。

保留零模型路径，将后备路径的正文边界、元数据和修改项合并为一次有严格 schema 的提取。是否连目标定位也能合并，需要用实际复杂页面判定，不许诺所有页面固定一次调用。

本轮直接执行旧分支提取函数的离线探针，确认：

- 模型超时及非 JSON 输出均返回“整页正文、空元数据”，没有向上抛出失败。
- `view_count: "1.2万"` 被转成 `12`，`like_count: "-3"` 被转成 `3`。
- 越界正文行号被静默夹进有效范围，无法区分正确结果与非法输出。

因此只复用一次提取的设计，保留当前严格类型/范围约束和错误传播。离线探针证明的是这些分支行为，不是模型提取质量。后续验收需要普通文章、长文、论坛、多主体页面，比较正文缺失与广告混入，才决定替换。

### 4. 分发队列操作收敛：值得做，不能靠删状态缩短

`routers/distribution_queue.py` 当前 1,330 行。单项重试、批量重试、按内容发送等入口重复修改排期、错误字段、审批标记，并各自提交和发事件。应让这些入口调用同一组明确的领域操作；批量与单项共用状态转换，不新建通用工作流引擎。

按队列项操作与按内容操作涉及不同选择范围，不能仅凭名称类似就删掉 API。保留调用契约，将权限、锁定检查、状态变更、任务记录和事件顺序统一，减少行为分叉。

旧 worker 缺少当前 `delivery_preparing/delivery_sending/delivery_unknown` 的同等处理。发送成功但回执丢失时，自动重试可能重复发消息；发送核对和领取身份必须保留。`tasks/distributor.py` 当前是媒体负载构造器，可移入 push 领域，但不能作为“重复 worker”删除。

另有 `routers/contents.py` 的处理阶段投影与手工触发编排可移入 service；单纯移文件不计作精简收益，只有消除多入口重复规则才值得展开。

### 5. Telegram Bot 改为同进程异步生命周期：条件明确后推进

当前管理代码包含子进程、PID 文件、Windows taskkill、信号停止、固定等待，以及 Bot 向本机 API 报心跳。旧版由异步 runtime 管理 Telegram Application 的 initialize/start/stop/shutdown，能删除这套进程控制胶水。

建议采用这个方向，先核对部署是否需要独立 Bot 进程和多 API worker。保留一个明确的 Bot 运行者、开关和任务回执，完成启停/配置重载后再删除独立 systemd 服务、PID 文件和自报心跳。Bot 业务命令的自身 HTTP 调用可随后收敛到现有业务 service，不一次改完所有入口。

范围只包括 Telegram Bot；不把 QQ Koishi 或 Telegram 账号同步顺手并入。代码内的默认拓扑不等于已经核验生产部署，本轮未连接服务器。

### 6. 向量索引：采用 SDK 原生异步/批量，不换整套实现

当前 Gemini 调用通过 `asyncio.to_thread` 包装同步 SDK，并在调用内创建客户端。已核对本机 `google-genai` 源码存在原生异步 `embed_content` 和批量请求实现；可复用客户端、按接口限制组织批次，减少线程包装与逐条网络往返。

当前 `batch_size` 控制应用循环，不能据此宣称已有模型 API 批量请求。批量化仍需逐内容校验版本、正确关联每个结果、保留失败范围和事务边界。

旧版删除当前媒体/页码等定位约束、采用固定检索上限、把 NumPy 相似度计算改为 Python 循环，不作为优化整体接收。也不为删除 SDK 而再造 REST 封装。主工作区已有未提交的索引提交/版本检查优化，应先衔接这些修改，避免重复重构。

### 7. 设置页面和任务界面：删重复表单，保留实际工作区

设置自动化页目前 1,625 行，包括模型配置、发现来源与诊断；收藏同步面板 972 行，包括策略、平台状态、预览、执行、最近任务。文件大并不等于全部多余。

先处理首次向导的重复配置，再在设置页复用模型地址/密钥/模型名的输入与保存反馈；保留不同用途字段及账号中心单一登录入口。收藏同步的预览、执行和结果是不同步骤，不能为了缩短页面去掉预览或错误反馈。

旧分支删除的 `dashboard_page.dart` 现在是动态流，`task_result_page.dart` 已承担失败详情、导航和重试；相关 provider、状态模型、渲染预设有实际消费者，保留。八个字体资源被主题/正文使用，删除会改变外观，不属于无用文件清理。

## 不采用的旧删除

- **后台运行账本与 SSE 事件整体删除**：当前任务结果、消息盒子和手机主动刷新依赖它们。旧事件实现 300 秒才心跳，当前前端 90 秒判定连接失活；直接采用会倒退已修复行为。内存事件替换持久事件还需确认跨进程生产者和断线补读契约，收益低于上述重复逻辑收敛。
- **旧数据库/队列重写**：当前已有 Alembic 和更简洁的初始化，`database.py` 94 行，旧版反而 329 行。保留当前迁移及状态结算，不重引旧方案。
- **删除 X 收藏抓取**：同名文件后来已实现真实网页书签抓取，被收藏工厂及账号认证使用；旧“未实现”判断过时。
- **删除 Agent API bridge**：已注册工具，使用进程内 ASGI transport，并有路径/方法白名单。可按实际使用量专门化常用诊断工具，但删除前必须有能力替代。
- **将 `/actions` 当死代码删除**：router 已挂载、OpenAPI 已公开。仓库内未找到明确的直接调用方，不足以证明外部无人使用；它是公开接口退役评估，优先级低。
- **删除维护/媒体补齐/依赖检查脚本**：Cookie keepalive、历史资产补齐仍有调用或文档入口，依赖检查仍在 CI 执行。保留必要能力。
- **恢复旧构建流程**：保留当前 Android 分 ABI、缓存及安装包交付改动。Makefile 中失效测试入口与已有未提交清理衔接，不另做一份。

文档和协作模板只能按现行入口及引用清理；不通过删除产品设计与现用说明凑减行数。

## 建议实施顺序与交付边界

1. **直接清理**：旧 B 站模型、未使用的 ArchiveBuilder 类；开发控制器与旧 smoke 脚本作为单独工具退役提交。
2. **优先重构**：RSS 共用解析；Agent 原生工具循环。两者分别交付，分别验收真实入口。
3. **界面收敛**：首次向导复用设置/账号页，模型表单去重；同步修正路由和初始化契约。
4. **后端收敛**：分发队列领域操作统一；Gemini SDK 原生异步与合理批量。
5. **需要额外证据的部分**：通用解析一次调用先验证内容质量；Telegram 同进程先核对实际部署拓扑，再实施。

每个改动从当前主线出发，不整体 cherry-pick 旧提交。已有未提交模型优化需先核对归属和交集。实施时报告实际新增/删除及保留行为，不预设“还要删五万行”。

本轮证据包括 Git 三方比较、当前调用/路由/配置追踪、已安装 SDK 源码，以及旧提取函数三类离线输入。没有调用真实模型、发送 Bot 消息、修改数据库、执行 Flutter 构建或生产部署；没有新增长期测试。
