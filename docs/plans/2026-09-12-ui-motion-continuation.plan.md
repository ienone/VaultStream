## 推进顺序

2026-09-13 用户追加重点：先判断任务该如何呈现，再调整组件样式。现有弹出模态框不是固定前提；按任务复杂度、编辑持续时间、与来源内容的关系及返回需求，选择二级页面、合适方向的临时弹层或原页面展开。简单选择保持紧凑，复杂或持续编辑有独立空间；不为变化而增加呈现方式。逐页检查层次不足、操作位置散乱，以及背景层、卡片和分界线重复表达同一分组的问题。优先用排版、对齐和留白表达层次，只有承担独立语义时才增加表面或边界。排期时间旧截图虽通过功能检查，用户已明确指出布局凌乱，不能再视为视觉验收通过。

后续逐页审查采用以下判断依据，具体页面仍以实际任务和运行效果决定，不机械套用：

| 任务性质 | 优先考虑的呈现方式 | 需要核对的关系 |
| --- | --- | --- |
| 少量参数、一次确认完成 | 紧凑对话框或与入口相邻的选择层 | 主操作突出，外框不为留空撑大 |
| 手机上的临时选择、操作列表 | 底部弹层；宽屏可用邻近弹层或侧面板 | 来源仍可识别，滚动、键盘及关闭可达 |
| 当前条目的附加信息、局部编辑 | 原位置展开或 supporting pane | 展开内容属于哪一条，收起后上下文是否保留 |
| 持续编辑、多分区、多步骤或需独立恢复 | 二级页面 | 返回层级、草稿保护、刷新与深链接 |

层次检查同时覆盖标题与正文比例、字段与所属标题的距离、主次操作位置，以及同一分组是否被底色、卡片和分隔线重复强调。修复后比较实际截图，不能只检查是否溢出或是否有圆角。

- 恢复真实运行基线，收尾图集首次按键；盘点页面、弹层及入口。
- 修复共享导航/动效的根因，收敛公共形状与临时 surface。
- 按收藏与阅读、搜索与 Agent、动态与消息、自动化与任务、账号与设置、捕获与播放逐组实现并复验；具体先后按真实缺陷影响调整。

## 验收与边界

2026-09-13 用户收敛验证方式：前端现场验收主要验证 UI / UX，包括布局、层次、空间、圆角、响应式、弹出组件、键盘遮挡和动效过程。删除、提交参数、状态隔离等常规功能优先通过代码逻辑检查与针对性测试验证，不再逐端重复手工点击；只在具体问题依赖真实交互且测试无法有效覆盖时，做最小现场复现。功能测试通过后直接推进视觉整改，不围绕同一控件反复补成功样本。加载、错误或提交中状态可用受控样本呈现，检查其视觉反馈不必触发真实业务副作用。

开始一个验收切片前先核对最新有效结果，旧过程记录中的待办不自动成为新任务。每次验证需对应尚未确认的可见问题或实际改动；已有结果覆盖且代码未受影响时直接复用。纯样式调整不重复跑业务套件，也不逐次构建 Web / APK；优先热重载和相关场景检查，累计到需要更新集成预览时再构建。过程记录只保留结论、证据与实际未解决项，不把临时工具试错扩充为产品验收要求。

Web 和 Android 按手机/平板/桌面适用断点、横竖屏、明暗主题、大字号与输入方式取样；不做折叠屏专项。过程动效用实际交互及必要录屏取证，组件事件测试只证明相应机制。临时脚本用后删除，长期仅保留高后果回归。状态分别记为未实现、部分实现、实现待验收、已验收；单次构建不证明整体视觉或真实设备行为通过。
