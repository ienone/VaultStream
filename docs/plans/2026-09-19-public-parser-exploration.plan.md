# 公开内容解析探索与优化

状态：公开解析优化与后端媒体归档主链收敛已完成本地验收；媒体自动补齐入口与客户端缓存身份仍待处理，见[媒体问题记录](../issues/2026-09-19-media-localization-integrity.md)。尚未部署。

## 目标与范围

依据用户在「汇总周末goal2自主推进成果」末尾明确的产品方向，优先提高分享链接的正文、媒体解析成功率，减少无必要的登录依赖、重复请求和模型调用。研究知乎、小红书、微博、Bilibili、X 和通用网页的现有 API、页面结构化状态与正常访客浏览器访问，不预设旧实现最优。

## 实施与验收

1. 记录当前调用链，使用少量公开链接比较匿名 HTTP、页面结构化状态和必要的已保存会话；只输出结构、长度、状态和字段完整性，不输出凭据或私人内容。
2. 对比同一对象身份与正文完整性。不得把摘要、登录墙、验证页或空响应作为解析成功；明确区分风控、登录要求与内容不存在。
3. 根据实测结果替换有问题的请求或解析路径，保留已有 ParsedContent 和安全抓取边界；公开解析不触发账号维护或自动同步。
4. 对确定性正文与元数据避免不必要的模型调用。复杂内容继续使用实际需要的模型步骤，不用静默猜测替代明确失败。
5. 完成针对性临时验收和必要的数据完整性回归，再运行后端检查；更新平台知识与同名 process 的实测结果和限制。

不自动提交、推送、部署，不启用同步、媒体批量下载或外部消息发送。

## 追加探索

继续验证知乎文章、问题和主页、小红书主页；测量现有公开解析耗时；对照同一浏览器内核的 Crawl4AI 与 Playwright，并追溯替换原因。图片缓存/下载/本地化最初只分析与复现；2026-09-20 用户要求重新处理媒体逻辑，后续已实施后端归档主链收敛，边界见[媒体问题记录](../issues/2026-09-19-media-localization-integrity.md)。

2026-09-20 用户校正：图像处理利用 WebP 等格式压缩存储、降低占用，不同时保留原图副本。后续优化优先收敛为下载、转码、落盘和引用更新，减少重复状态和处理，不扩展多变体或通用修复框架。
