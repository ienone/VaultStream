# 平台解析器真实样本与字段完整性实施计划

## 文档状态

completed-with-known-limit

## 背景

VaultStream 已支持知乎、小红书、Bilibili、微博、Twitter/X 等平台，但单元样本、真实平台当前行为、内容入库字段和前端模板所需信息之间仍可能存在漂移。本计划以用户从真实页面收集的公开 URL 为证据，验证解析可用性并修复高价值字段缺口。

## 目标

- 为各平台主要内容类型建立可重复的真实 URL 样本矩阵。
- 通过真实内容创建/解析 contract 区分“请求失败”“解析成功但字段不完整”“入库映射丢失”。
- 对照平台当前可用的结构化 API、页面嵌入数据和现有适配器策略，优先采用稳定、可测试的确定性解析路径。
- 对照 `ParsedContent`、`Content` ORM、内容 schema 和媒体资产输入，修复错误映射、遗漏映射和缺少承载字段的高价值信息。
- 更新平台适配器知识库和内容模块文档，记录当前事实、限制与验证样本类型。

## 范围

- 平台：知乎、小红书、Bilibili、微博、Twitter/X。
- 内容类型：各平台当前明确支持的文章、帖子/动态、视频、图集、问答、用户主页等主要类型。
- 后端：平台适配器、解析辅助模块、内容服务映射、内容 schema/ORM（仅在确有高价值缺口时扩展）、相关测试。
- 验证：公开 URL 页面可达性、解析 API 响应、数据库落库结果和媒体/统计/作者等关键字段。

## 非目标

- 不读取或导出内置浏览器 Cookie、Local Storage、密码或会话存储。
- 不把收藏同步、账号登录和解析器合并成同一协议。
- 不在本计划中重做前端模板或统一媒体访问方案；只保证解析输出提供其已有 contract 所需信息。
- 不为绕过平台风控实现高维护成本的隐藏兼容链路；结构化 API 不稳定时保留明确、可诊断的页面或浏览器路径。
- 不抓取完整评论列表、关注列表等高成本分页集合，除非它们是当前内容语义不可缺少的一部分。

## 实施步骤

1. 核对分享/内容解析 API、适配器注册、`ParsedContent`、ORM、schema 和内容服务映射。
2. 从内置浏览器的公开页面收集分平台、分类型规范 URL，记录页面可见类型，不提取登录凭据。
3. 调用真实解析入口并记录成功状态、错误分类、解析耗时和关键字段完整度。
4. 对失败样本检查 URL 识别、规范化、API/SSR/HTML 获取、反风控和异常分类。
5. 对成功样本逐层比较平台原始结构、`ParsedContent`、ORM 落库与 API 返回，形成字段缺口清单。
6. 优先修复可由稳定结构化来源获得、对检索/展示/归档有明确价值的缺口，并补固定样本测试。
7. 重新运行真实样本矩阵与后端测试，更新 adapter、内容模块和 API/数据库文档。

## 验收标准

- 每个平台至少有一个主要内容类型完成真实解析；无法验证的类型明确记录原因。
- 真实失败能归入稳定错误类别，不暴露 Cookie、签名或敏感请求参数。
- 标题、正文、作者、发布时间、媒体、统计、平台 ID、内容类型和布局类型在可获得时正确贯通到内容 API。
- 新增或修改的字段有 ORM/schema/service/测试/文档一致性证据。
- 默认后端测试通过；依赖真实平台的探针留在 `backend/manual_tests/` 或执行记录中，不进入常规测试集合。

## 实施结果（2026-07-28）

- 从内置浏览器公开页面收集并通过只读诊断接口验证 16 个样本：15 个成功，知乎问题页 1 个因 API `10003` 与 HTML 403 失败。
- 成功样本：知乎回答/文章/用户，Bilibili 视频/番剧/直播，微博文本/长图/视频，Twitter 文本/图片/引用/视频，小红书图文笔记 2 条。
- 统一了生产解析和诊断解析的数据库 Cookie 加载，修复诊断端点引用不存在作者字段的问题，并扩展了不含敏感原始值的字段完整度输出。
- 修复紧凑计数、布局选择、话题标签、引用推文、视频时长，以及头像误入正文媒体/封面的映射问题；现有通用统计列、`extra_stats`、`source_tags`、`rich_payload` 和 `archive_metadata` 足以承载本次发现，不新增数据库列。
- 真实平台探针保留在忽略的 `backend/manual_tests/`，正式回归测试使用固定响应/HTML 样本。
