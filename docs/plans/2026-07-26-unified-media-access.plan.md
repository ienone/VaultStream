# VaultStream 统一媒体资源与访问方案

## 状态

active

## 背景

当前内容模型用 `cover_url`、`thumbnail_url`、`author_avatar_url` 和 `media_urls` 等单值字段表达媒体。归档任务实际已经保留部分原始 URL、本地存储 key、WebP 与缩略图信息，但内容 API 没有把这些信息组织为可选择的候选来源，前端只能把一个 URL 映射成本地媒体或图片代理地址。

本地媒体与控制 API 又共用同一个全局 API Token。普通 JSON API 可以稳定发送鉴权头，浏览器原生图片、视频、音频、缓存和 Range 请求却不适合携带这一全局凭证。继续为单个图片组件增加例外无法覆盖未来的音视频播放，也会把安全策略、URL 规则和失败降级散落到各个模板。

关联问题：`../issues/media-proxy-image-access.md`。

## 目标

- 用一套媒体模型覆盖封面、头像、正文图片、图集、视频、音频、poster 和其他附件。
- 优先读取服务器已归档、校验和转码的媒体变体；失败时依据明确策略选择下一候选。
- 将控制 API 鉴权与媒体读取授权拆开，媒体请求不再携带全局 API Token。
- 让卡片、详情、富文本、播放器和分发服务共享同一份来源选择语义。
- 保留原始来源、归档状态、失败原因和可修复性，不用占位图掩盖真实数据问题。
- 重构完成后删除旧的单 URL 映射和默认代理所有外链逻辑，不长期维护两套路径。

## 非目标

- 本计划不决定所有平台是否默认永久下载原视频或原音频；保留策略仍由内容价值、用户设置和存储成本决定。
- 不在媒体 URL 中放置平台 Cookie、全局 API Token 或其他账号凭证。
- 不通过放宽回环、私网和重定向检查来解决远端媒体不可达。
- 不为每种内容模板建立独立媒体协议；模板只决定媒体角色和呈现方式。
- 不在本计划中完成全局播放器、字幕、章节和播放队列的完整产品体验。

## 统一领域模型

### MediaAsset

`MediaAsset` 表示一个有业务身份的媒体对象，而不是某个具体 URL。

建议字段：

- `id`、`content_id`、`position`
- `media_type`：`image`、`video`、`audio`、`document`、`other`
- `role`：`cover`、`avatar`、`body`、`gallery`、`poster`、`attachment`
- `original_url`：来源平台提供的原始地址
- `alt_text`、`caption`
- `width`、`height`、`duration_ms`
- `archive_status`、`last_error`、`repairable`
- `metadata`：平台特有但不参与核心选择的补充信息

### MediaVariant

`MediaVariant` 表示同一资产可供读取或播放的一个版本。

建议字段：

- `id`、`asset_id`
- `variant_kind`：`thumbnail`、`optimized`、`original_archive`、`poster`、`stream`、`transcode`
- `storage_key`：本地对象存在时填写，不持久化带 host 或签名的访问 URL
- `mime_type`、`codec`、`container`
- `width`、`height`、`bitrate`、`size_bytes`
- `status`：`ready`、`processing`、`failed`、`missing`
- `checksum`、`created_at`

原始远端地址属于资产来源，不伪装成本地变体。运行期 API 根据资产、变体和请求场景生成有序的 `MediaSource`。

### MediaSource

`MediaSource` 是返回给客户端的短期读取候选，不直接作为数据库事实保存：

```json
{
  "url": "/api/v1/media/...?...",
  "source_kind": "local_signed",
  "variant_kind": "thumbnail",
  "mime_type": "image/webp",
  "width": 720,
  "height": 405,
  "client_fetch_allowed": true,
  "expires_at": "..."
}
```

内容列表和详情返回相同的 `MediaAsset` 结构；列表只裁剪不需要的元数据和候选数量，不另建一套封面事实源。

## 访问授权边界

### 控制面

内容修改、同步、账号、设置、Bot、Agent、任务和诊断等 JSON API 继续使用 API Token。该 Token 只通过请求头传递，不进入媒体 URL。

### 媒体面

本地媒体采用独立 HMAC 签名 URL。签名至少绑定：

- `storage_key`
- 允许的变体或操作
- 过期时间
- 可选的内容或资产 ID

媒体签名密钥与 API Token 分离。签名 URL 只能读取一个媒体对象，不能访问其他 API。服务端验证签名后继续执行路径穿越防护、Range、ETag、Content-Type 和缓存策略。

签名过期时，客户端通过已鉴权的内容/媒体 manifest API 刷新候选；播放器和图片组件不自行拼接新签名。生产日志和错误上报应隐藏签名 query。

本地仅回环开发环境可以提供显式的免签调试开关，但默认行为和生产 contract 仍以签名 URL 为准，不能通过是否存在 API Token 隐式切换。

## 来源排序与降级

候选顺序由后端根据用途、格式支持、归档状态和安全策略生成，前端只执行顺序和失败规则，不重新猜测平台域名。

### 图片类用途

1. 本地 WebP/AVIF 缩略图或优化图。
2. 本地归档原图。
3. 后端安全代理的远端原图。
4. 标记 `client_fetch_allowed=true` 的原始远端 URL。

卡片、详情头图、头像、正文图片和图集使用同一顺序；区别只在请求的用途和尺寸。

### 视频类用途

1. 本地浏览器/设备兼容转码。
2. 本地归档原视频。
3. 后端允许的远端流或代理源。
4. 标记为客户端可直连的原始源。

poster 是独立的图片资产或图片变体，不从视频 URL 临时猜测。

### 音频类用途

1. 本地兼容转码或归档音频。
2. 后端允许的远端流或代理源。
3. 标记为客户端可直连的原始源。

音频封面仍是图片资产；不能把音频 URL 塞入图片字段。

### 失败规则

- 签名过期或无效：刷新 manifest 一次，再重试同一本地候选。
- 本地 404、损坏或解码失败：进入下一候选，并上报资产待修复。
- 远端 502/504：只在后端明确允许客户端直连时进入原始 URL。
- SSRF、协议或来源策略拒绝：终止该远端分支，不允许客户端绕过后端安全决定。
- 格式或编解码器不支持：选择下一兼容变体。
- 所有候选失败：返回稳定的语义占位，并保留可诊断状态。

一次展示只允许一个候选处于活动加载或播放状态，避免同时下载多个大媒体。失败切换次数必须有上限，候选 URL 去重后再执行。

## 后端职责

- 解析与归档阶段创建或更新 `MediaAsset` 和 `MediaVariant`，保留原始来源与处理结果。
- Presenter/manifest service 根据 `purpose`（如 `card`、`detail`、`playback`）生成有序候选和签名 URL。
- 图片代理回归透明、安全、有限缓存的远端读取职责；转码和永久归档由后台任务完成。
- 音视频媒体端点支持 Range、正确 MIME、长度、ETag 和条件请求。
- 本地候选缺失时记录可观察的修复状态；可重建媒体允许重新归档，不在请求线程同步执行大型转码。
- 删除内容或资产时按引用计数处理物理对象，不删除仍被其他内容或变体引用的 blob。

后端不得要求前端根据域名、文件扩展名、URL 形态或异常文案推断候选优先级和安全策略，也不得把平台 Cookie 或全局 API Token 下发为媒体凭证。

## 前端职责

- 建立统一 `MediaAsset`、`MediaSource` 类型和 source resolver。
- 图片渲染器、富文本、图集和播放器都使用统一候选执行器；模板不得自行调用 `mapUrl()` 或猜测鉴权头。
- 区分加载中、无媒体、远端失败、本地损坏、授权刷新失败和格式不支持。
- 页面切换或 shared transition 不重复创建媒体请求；播放会话持有资产 ID 和当前 variant，而不是只持有临时 URL。
- 图片可以使用统一缓存；音视频尊重 Range、暂停、恢复和平台播放器生命周期。

前端不得自行把任意外链包装成代理 URL，不得生成媒体签名，不得绕过后端的安全拒绝，也不得在各内容模板中分别维护来源优先级。

## 端到端职责矩阵

| 环节 | 后端负责 | 前端负责 | 共同 contract |
| --- | --- | --- | --- |
| 平台解析 | 提取原始媒体、角色、顺序和来源证据 | 不参与平台抓取 | `media_type`、`role`、`position` |
| 归档与转码 | 下载、校验、转码、生成缩略图/poster、写入 blob | 展示处理状态，不在设备上替后端永久转码 | `archive_status`、`variant_kind`、`last_error` |
| 资产持久化 | 保存 `MediaAsset`、`MediaVariant`、引用和校验信息 | 不持久化服务端事实，只缓存展示所需 DTO | 资产与变体 schema |
| 候选生成 | 按用途、可用性、格式和安全策略排序并去重 | 按返回顺序执行，不重新排序 | `MediaSource[]`、`purpose` |
| 本地媒体授权 | 生成并验证资源级签名，限制 key、变体和有效期 | 使用签名 URL；过期时请求一次 manifest 刷新 | `expires_at`、稳定错误码 |
| 远端代理 | SSRF、重定向、Content-Type、大小、超时和平台请求头 | 只使用后端返回的代理候选 | `source_kind=remote_proxy` |
| 原图直连 | 判定是否允许客户端直连并设置标记 | 仅在标记允许且前序候选失败时尝试 | `client_fetch_allowed` |
| 图片显示 | 返回适合用途的尺寸和格式候选 | 解码、缓存、占位、切换候选、语义描述 | 加载/失败状态枚举 |
| 视频/音频播放 | 提供可播放变体、Range、MIME、长度和稳定资产身份 | 选择设备支持来源，管理播放、暂停、进度和生命周期 | codec/container/duration 能力字段 |
| 授权失败 | 区分过期、签名无效和无权访问 | 仅对过期执行一次刷新；其他错误停止本地分支 | `media_signature_expired` 等错误码 |
| 资源损坏 | 标记缺失/损坏并提供重建入口或任务 | 降级显示并上报当前候选失败，不直接修改资产事实 | `repairable`、资产状态 |
| 删除与清理 | 引用检查、事务、物理 blob 清理 | 发起用户动作并展示结果 | 删除 API 与结果 schema |
| 诊断与观测 | 记录 request ID、资产 ID、候选类型和失败分类，隐藏签名 | 展示可理解状态并在诊断动作中回传 request ID | 稳定错误码和 request ID |

### 决策权边界

- “这个远端地址是否安全、是否允许直连”只由后端决定。
- “有哪些本地或远端候选、它们的默认顺序是什么”只由后端决定。
- “当前设备能否解码/播放某个已允许候选”由前端运行期判断。
- “候选失败后界面怎样保持稳定、是否显示占位或播放错误”由前端决定。
- “是否永久归档、生成哪些变体”由后端依据用户可见配置和任务策略执行；前端只提供控制面。
- “字段、错误码、媒体类型和状态含义”属于前后端共享 contract，任何一端变更都必须同步类型、文档和测试。

### API 交付边界

后端内容列表、内容详情和媒体 manifest 都返回同一媒体 DTO。前端生成代码或强类型模型直接消费该 DTO，不允许通过 `Map<String, dynamic>` 猜测不同接口的字段。

后端返回的 URL 已是可请求地址：本地来源带资源级签名，代理来源带完整代理地址，原始来源只在允许直连时出现。前端不再调用 `mapUrl()`、`mapPlayableUrl()` 或 `buildImageHeaders()` 改写这些地址。

前端向后端发出的只有三类媒体相关动作：读取带媒体 DTO 的内容、按资产刷新 manifest、显式触发重新归档/修复。图片或播放器自身不触发同步转码、数据库写入或平台登录。

## 数据迁移与旧路径删除

1. 从现有 `cover_url`、`author_avatar_url`、`media_urls`、`rich_payload` 和 `archive_metadata.stored_*` 回填资产与变体。
2. 对能同时找到原始 URL 和本地 key 的记录建立同一资产的多来源关系；无法确定关系时标记待修复，不按文件名猜测。
3. 完成回填一致性检查后，内容 API 改为统一媒体 contract。
4. 同步切换卡片、详情、富文本、图集、分发和播放器调用方。
5. 删除 `mapUrl()`、`mapPlayableUrl()`、图片专用鉴权头和旧媒体字符串字段的运行时读取路径。
6. 数据库旧列只在迁移验证窗口保留，确认无读取方后通过后续 schema migration 删除；不建立永久双写。

## 实施阶段与出口

### 当前实施证据（2026-07-26）

- 已建立统一资产/变体表、内容 API 媒体 DTO、资源级签名读取和独立签名密钥。
- 已从 108 条现有内容执行可重复回填：102 条有候选，共 1086 个资产、1964 个本地变体；回填前数据库备份通过完整性检查，回填后无缺失本地变体。
- 卡片、详情封面/头像、正文、媒体网格、全屏图集及音视频初始化已执行统一候选；列表响应模型已验证不会丢弃 `media_assets`。
- 尚未完成 manifest 过期刷新、失败上报、Range/播放恢复、分发调用方迁移和旧字段删除，因此计划保持 active。

### 1. Contract 与安全基础

- 确认数据库表、Pydantic schema、签名格式、过期与刷新规则。
- 覆盖签名伪造、越权 key、路径穿越、过期、Range 和日志脱敏测试。
- 出口：客户端无需全局 API Token 即可读取一个授权媒体，但不能扩大到其他资源。

### 2. 归档与 manifest

- 图片、视频和音频归档统一写入资产/变体模型。
- 完成现有数据回填工具和只读一致性报告。
- 出口：真实样本能同时返回本地优先候选和安全远端候选。

### 3. 全前端媒体执行器

- 建立共享候选状态机、图片渲染器和音视频 source adapter。
- 一次性替换卡片、详情、头像、富文本和媒体网格中的旧 URL 映射。
- 出口：图片场景不再直接依赖 `mapUrl()`；音视频可使用同一资产 contract 选择来源。

### 4. 音视频与分发收敛

- 接入 Range、播放恢复、poster、后台播放所需的稳定资产身份。
- 分发服务按目标能力选择可上传的本地变体或可访问远端来源。
- 出口：播放与分发不再读取旧媒体字符串字段。

### 5. 清理与迁移完成

- 删除旧 API 字段、旧映射函数、媒体请求中的 API Token 和永久双写。
- 归档或关闭媒体访问 issue，更新前后端当前实现文档。
- 出口：代码搜索、数据库检查和测试证明旧路径没有读取方。

阶段只描述该统一方案内部的依赖和验收出口，不代表 VaultStream 的全局开发路线。进入实际实施后，如需跨会话记录真实进展，再创建同名 process。

## 验收矩阵

- 媒体类型：图片
- 角色：封面、头像、正文、图集、poster、附件。
- 来源：本地优化、本地原始、远端代理、允许直连原始地址。
- 状态：成功、签名过期、本地缺失、远端超时、安全拒绝、格式不支持、全部失败。
- 平台：Flutter Web
- 布局：卡片、详情、沉浸媒体和全局播放会话。

必须验证：

- API Token 不出现在媒体请求、URL、浏览器历史或普通日志中。
- 签名不能改 key、变体或过期时间后继续使用。
- 本地媒体优先命中；本地失败时只按 contract 降级。
- 图片不出现红色裂图；无可用媒体时显示稳定占位及可诊断状态。
- 视频和音频支持暂停、恢复、Range 与来源切换，不重复下载完整文件。
- SSRF 私网、回环、重定向和 DNS 变化测试继续通过。
- 迁移前后资产数量、引用关系和物理 blob 引用检查一致。

## 风险与回滚边界

- 数据迁移错误可能把原始来源和本地变体关联错位；迁移必须先生成只读报告，并保留数据库备份和可重复回填工具。
- 签名 TTL 过短会造成频繁刷新，过长会扩大泄露窗口；需要用真实滚动、详情停留和长音视频播放验证。
- 远端直连受 CORS、防盗链和 Cookie 影响，必须由后端显式标记，不能作为万能 fallback。
- 音视频转码成本较高；媒体模型先支持“远端或本地原始可用”，不要求每条内容立即生成所有变体。
- 回滚只允许回滚 schema/API/前端整个迁移批次；不以运行时条件长期保留新旧选择逻辑。
