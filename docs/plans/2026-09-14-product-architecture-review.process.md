## 本轮交付：先修复连续性和证据完整性

- 解析：30 分钟固定租约，沿用 Task 的 started_at 和单调递增 retry_count 表示本次所有权；到期有界接续，耗尽后 Task 与仍处理中内容在同一事务失败。结果、媒体事实和 Task 完成原子提交，写入前重新读取人工修订和删除状态；迟到旧执行不能写新结果或结算新租约。
- 分发：10 分钟租约和每次唯一 token，持久区分准备/已进入发送边界/结果未知。只有未调用发送服务的准备中断可自动重试；未知结果隔离并生成持久消息。前后端普通重试、批量操作、force 与 Agent 不绕过核对；无关目标继续执行。沿用显式人工发送可绕过自动暂停的既有语义，目标、规则、审批和聚合授权仍必须重读。
- 核对：消息 → 对应队列项 → 已找到消息/已核实未发送 → 原子保存并关闭通知。确认已送达要求消息 ID；确认未发送不自动排期。界面说明真实状态，过时观察返回冲突，失败保留草稿。
- 证据：expire_only、archive、hard_delete 共用“未采纳且无依赖”条件；事件任意角色成员、明确保存/收藏来源、发送队列/记录以及父子内容不被候选 TTL 独立清理。无依赖过期候选仍按策略清理，不把所有材料永久保留。

本轮不增加数据库列、持久化枚举或依赖。发送阶段暂存于已有 last_error_type；不是另起一套工作流。解析对已成功内容的重复任务直接完成，不再进入隐式补归档并覆盖正文的旧分支；需要重新解析时走现有显式入口。固定租约尚无心跳，超长执行会失去提交资格，需要按到期流程接续或核对。

## 下一切片与不外推的边界

下一步按阶段 1 做“来源与账号 → 一种已支持平台收藏 + RSS/TG → 可读结果”，统一同步编辑入口、来源历史与耐久后处理。当前内容写入/游标与后处理之间的内存交接仍未替换；解析完成不代表摘要、索引、自动审批和分发已耐久完成，不能把 P0 接续等同于整条持续任务完成。

阶段 2 才同时落地真实关注、事件增量、统一动态与新三导航；本轮保留现有导航，不发布空关注页。随后推进上下文搜索/Agent 与简报/自动任务。

凭据与备份方案从现在明确边界：凭据由唯一服务接管，部署密钥外部注入，普通配置导出不含秘密；备份分别覆盖数据库、媒体、可重建索引和凭据恢复依赖。部署密钥保管、轮换与丢失恢复方式尚待确认，本轮不实施加密 schema/密钥迁移，不宣称完成备份恢复演练。

TTL 本轮保护现有持久依赖，不恢复已被旧版本删除的证据；来源版本/片段引用及用户主动不可逆擦除的影响确认仍属后续设计。所有平台真实同步、长时间持续运行、远端送达核查仍需用户授权后专项验收。
