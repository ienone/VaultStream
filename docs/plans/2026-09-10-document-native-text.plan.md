# 文档原生文本阅读与页码引用

## 状态

in_progress。2026-09-10 已实施原生 PDF 阅读切片，实际结果与剩余工作见 [执行记录](2026-09-10-document-native-text.process.md)。以下问题是实施前基线，不再表示当前代码完全缺失这些能力。

## 实施前已确认问题

- `ContentService.create_files_capture` 保存原文件、资产与用户 note，body 仅为保存说明，没有文档文本提取。
- `PostIngestService` 只有摘要、索引、评分与分发编排，没有 PDF 文本生产步骤。
- `_DocumentBody` 仅呈现保存说明与原文件入口；检索与 Agent 无稳定的文档页码证据。
- 因此“文件保存成功”和“索引存在”不能证明 PDF 正文可检索。用户说明必须继续与文件原文区分。

## 目标与边界

为有原生文本层的本地 PDF 建立原文件 → 按页提取 → 完整阅读 → 页码检索/引用的闭环。保留多附件同一内容对象，页码必须与明确的文档资产绑定。扫描页、加密文件、提取失败分别显示真实状态，不把空文本当作成功识别，不调用外部模型冒充本地提取。

这个切片不宣称完成扫描 OCR、复杂版面恢复、表格语义、幻灯片或所有 Office 格式；这些仍属于系统构想的未完成目标。原生文本层也可能阅读顺序不佳，须用中文和多栏样本检查，不能靠字符数验收。

## 实施设计

1. 采用独立本地文档提取 service，优先评估 pypdf 原生文本提取。依赖需加入后端正式依赖和版本约束，不能依赖 Codex 专有运行时。提取不在上传事务或事件循环内执行；通过现有任务账本表达开始、成功、空文本、失败，保留手动重试入口。具体文件/页数/时间限制按样本测量确定。
2. 从当前内容所属、已归档的 document 资产读取原文件，执行 storage 根目录、资产归属和文件类型校验。结果提交前重新检查资产身份及内容版本，避免并发删除/替换后提交旧文本。用户说明及人工编辑字段不被覆盖。
3. 按现有 rich_payload.chunks 统一保存页面内容，显式附带 document 资产 ID、从 1 开始的页码、原生文本来源标记；不在两套 JSON 中复制整份正文。与音视频时间段区分，页面 DTO 需重新验证所属文档资产后暴露，禁止前端从未校验原始 payload 猜测页码。
4. 文档详情增加按页阅读入口，原文件仍可打开；多附件按资产选择，同一资产内按页定位。完整文本可选择复制，保存说明保留独立标题。搜索结果和 Agent 引用路由必须同时包含内容、文档资产、页码，并实际进入目标页。
5. 现有全文/语义索引与 Agent 读取复用页面切片；索引不得只消费文件名/保存说明后声称文档正文已就绪。原始 PDF 更换或提取重试后，过期页切片和索引同步失效。外部模型验收仍遵守当前具体数据披露授权限制。

## 验收

- 中文文本 PDF、多栏英文 PDF、扫描页、混合文本/扫描、加密/损坏 PDF、多附件分别检查；原文件始终保留，错误不制造成功正文。
- 以来源页实际内容核对提取文本、换行/阅读顺序和末尾，不仅检查非空；从页内独特关键词命中后可定位原页。
- 浏览器普通入口验证阅读、页码切换、搜索返回和 Agent 页码引用；原生设备能力不由 Web 截图外推。
- 临时解析样本与验收脚本用毕删除，只有资产越权、并发替换/删除和索引一致性等高后果边界考虑长期回归。
- 不启用分发、不向他人发送内容，不将未授权正文发送给模型。真实外部模型效果与本地提取效果分别记录。

## 调研依据

- [pypdf 原生文本提取说明](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)：原生提取与 OCR 不等同，PDF 的文本顺序与页面视觉布局也不等同。
- [PyMuPDF 文本提取说明](https://pymupdf.readthedocs.io/en/latest/recipes-text.html)：具备布局相关提取能力，可作为样本比较对象；尚未引入项目依赖。
