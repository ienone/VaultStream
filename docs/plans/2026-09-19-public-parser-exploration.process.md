## 核心证据与取舍

### 知乎

入口线索来自作者维护的 [sharextract 知乎实现](https://github.com/wuaishare/sharextract/blob/main/sharextract/extractors/zhihu.py)，随后独立请求知乎第一方 `/tardis/zm/ans/{id}`、`/tardis/zm/art/{id}` 并核对 `window.g_initialProps` 的实际 contract。没有运行下载的参考代码。

回答 `91100582445` 的 Tardis 与正常桌面页面正文，经 HTML 解码和去空白后完全一致：长度 2996 UTF-16 code units，FNV-1a 32 位指纹均为 `1721548468`。桌面原始 HTML 的 48 个图片标签为 24 张图片各一份 noscript 与懒加载副本，去重后对应阅读页 24 张图。

阅读页 `created=1752530795` 等于桌面 `updatedTime`，而桌面 `createdTime=1738458995`。因此新解析不伪造发布时间或缺失的作者 ID。保存账号时仍优先已有 API，以保留更完整元数据；匿名阅读页独立不带账号 Cookie。

本机当前数据库没有保存知乎 Cookie，不能把旧会话的账号态结论写成本轮验收。共享 WebKit 和新建无头 Chromium 均未复现正常桌面浏览器的知乎成功；没有增加未经验证的浏览器重试链。公开解析不再自动触发账号指纹刷新。

### 小红书

正常匿名网页的 SSR 明确包含 `note.noteDetailMap[id].note`。对照请求显示：仅 User-Agent/Accept 返回空壳；使用同一适配器 UA，并携带网页导航的 client hints 与 `Upgrade-Insecure-Requests` 后返回详情。原始 token 尾部 `=` 与 URL 编码 `%3D` 两者均成功，不能把差异归因于 token 编码。

另在正常网页操作中观察到 `/api/sns/web/v1/feed` 的真实 200 响应：`success=true`、`code=0`，`data.items[].id` 和 `note_card.note_id` 均对应请求对象。API 与 SSR 均按对象身份提取，拒绝第一条推荐内容代替目标。

实际 SSR 作者字段为 `userId`，视频地址为 `media.stream.h264[].masterUrl`；归一化后复用现有归档 contract。图片和视频各用 Range 读取 1024 字节，均返回 206，类型分别为 `image/jpeg` 与 `video/mp4`。没有下载完整视频，也没有声称覆盖所有分享链接、最高画质或账号签名链路。

### 通用网页与微博

通用抓取将 Markdown 协商与 HTML 读取合为一次 HTTP 请求，保留安全 URL/重定向、响应大小与 MIME 限制；内容不足才进入现有共享 WebKit。404/410 不做浏览器重试，429 保留可重试错误。明确验证页不送入正文提取。

Telegraph 已实测零模型完整解析；schema.org 单一 `articleBody` 路径仅通过离线结构验收。对音视频/iframe 和明确付费标识不走简单文章提取，复杂页面仍走既有模型流程。此处没有新增通用“自动判断完整性”的模型调用。

微博长文故障注入覆盖超时、缺字段与空正文，均明确失败且使用同一代理，不产生“成功但截断”的结果。移动端匿名接口未成功，未加入未经验证的替代路径。
