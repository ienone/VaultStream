# 来源接入、处理与分发闭环

## 状态

active

## 目标与边界

在当前共享工作区实现来源/个人收藏 → 解析 → 持久账号态 → 整理聚合 → 受控模型处理 → 策略分发。复用现有 Adapter、任务、配置、知识事件和分发队列，不增加第二套认证或工作流框架。不改生产数据，不自动提交、推送或部署。前端只补必要控制面。

## 阶段与验收

1. 聚焦审计：核对平台知识、真实 contract、调用链与缺陷，逐步补齐上述事实，不把历史报告当当前验收。
2. 接入与身份：统一平台差异边界，修复分页、恢复和账号问题；用隔离数据库验证重复内容、部分失败、失效及末页。
3. 处理与分发：完成可控聚合/模型处理与订阅分发链路，复用持久任务结果与知识事件；补必要控制面。
4. 集成交付：根目录 .venv 执行针对性与现有回归、契约门禁；更新模块/平台文档，检查共享差异和临时文件。

用户已授权合理使用账号与模型；外部发送尚需具体授权。公开只读契约调查可以执行。明确区分本地功能证据、平台实测与部署状态；外部受限不包装成成功，也不阻止独立实现。

## 自动聚合切片的具体边界

新增默认关闭的内容聚合开关，复用发现任务的周期检查与现有文本模型工厂。按持久进度选择新增的已解析来源，每批最多 20 条新增及 10 条最近七天关联材料；模型只负责判断共同事件并给出带原文短引句和内容 ID 的结构化综合。无法形成共同事件允许返回空分组，不能硬凑汇总。新建标明 AI 生成、证据未确认的聚合文章，并创建事件或向未被人工修改的自动事件追加来源，不自动修改人工事件、评分、原文或原摘要。输入版本变化、模型错误或引用越界不提交产物与成功进度。

聚合文章使用原有 contents/is_synthesis，事件使用原有成员关系；保存结果与进度同一事务，持久任务账本记录输入版本、输出资源 ID 与失败。默认不产生外部推送，独立开启聚合结果分发后仍经过当前分发规则、审批与暂停开关。开启 UI 明确说明模型调用和原文发送范围。先隔离验证真实数据库/队列、模型仅替换边界，不能将结构验证说成真实智能质量验收。

## 继续执行纠正

上一轮完成的是阶段实现，不是总体目标完成。继续比较微博/X 的 API、网页请求与会话复用方案，补足可维护接入；复审聚合跨批关联及整个处理/分发链路。公开研究、只读核验和独立实现继续自主推进，仅具体账号授权、付费调用或实际发送按对象处理。正常使用验收优先，不扩大极端字号测试。

## 继续执行的接入与事件更新决策

微博采用现有 SUB 登录：移动 config 识别账号，桌面 all_fav 读取分页；匿名实测 config ok=1/login=false、桌面接口跳转登录。原游客页面 HTTP 200 健康检测移除。

X 比较官方 OAuth、直接 GraphQL 客户端与网页读取。选择复用已有服务端浏览器及显式保存的 X Cookie：网页生成当前查询 ID/功能开关/请求头，Adapter 只修改 Bookmarks GET 的 count/cursor，读取已核对的 Timeline v2；访问验证立即停止，不提取用户浏览器配置，不安装独立 CLI，不实现静默 fallback。匿名浏览器实测已得到 auth_required。用户已授权合理使用账号；用户随后保存 X 登录，已完成真实书签续接和同会话内容解析验收。

跨批聚合每次最多 20 条新内容与 10 条最近七天已处理来源。模型可明确指定续接候选事件，必须引用至少一条原事件来源和一条本轮新来源。仅自动生成后未被人修改的事件可成为候选；最新自动报告记录事件版本，手工修改版本即退出自动续接。续接只追加来源与新综合稿，不覆盖人工内容，不自动合并两个事件。来源、事件版本和成功游标仍同一事务验证保存。
