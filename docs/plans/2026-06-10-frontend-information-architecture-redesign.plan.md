# VaultStream 前端信息架构与体验设计方案

## 状态与职责

active · 2026-09-14 重审版，目标设计，尚未整体实施。

2026-09-05 对产品目的与需求的确认继续作为背景；本轮按用户要求重新判断页面与导航，不把历史确认解释为三项旧导航不可变。**本版建议动态 / 资料库 / 关注为主导航，来源与账号 / 自动任务为二级工作区。** 这是本轮提出的结构选择，不冒称用户已逐项批准。

## 1. 从用户目的决定层级

用户日常只需回答三个问题：现在有什么新内容或变化；之前保留的材料在哪里；正在关注的事情进展如何。同步、解析、模型和推送应该支撑这些任务，而不是要求用户巡视流水线。

| 层级 | 目标入口 | 首要职责 |
| --- | --- | --- |
| 连接与初始化 | 连接、必要引导 | 建立可用环境，不与日常导航并存 |
| 主目的地 | 动态、资料库、关注 | 看变化、用材料、持续追踪 |
| 二级工作区 | 来源与账号、自动任务 | 连接输入与身份；管理持续目标和输出 |
| 跨场景工具 | 搜索、保存、Agent、消息、设置、播放器 | 保持范围与会话，不重复创建业务首页 |
| 对象与运行 | 内容、事件、来源、账号、任务目标、规则、一次运行 | 深链接到具体对象，回到真实发起位置 |
| 临时表面 | 筛选、少字段编辑、确认、预览 | 一次小任务；不放整套多步业务 |

原设计中“主导航始终为动态/收藏库/自动化”“越窄越用紧凑网格”“所有详情都须共享容器形变”“先造统一转场协调框架”等要求不再适用。保留目的明确的标准 Material 路由、连续阅读和状态恢复；不为新方案恢复早期已删除的 Discovery/Review 页面。

## 2. 导航、路由与所有权

### 2.1 Root Shell 的建议布局

- **手机竖屏**：底部固定动态、资料库、关注三个带文字目的地；页头保留标题、一触搜索和有名称/语义的“工作区”入口。工作区展开为可滚动侧面板或 sheet，明确列出来源与账号、自动任务、Agent、消息、设置。未读/待确认徽标进入同一消息入口，不再复制铃铛。
- **正常桌面**：左侧导航分组常驻，主目的地在上，来源与账号、自动任务在中，Agent、消息、设置在下；共享页头只放搜索、保存与当前页面必要动作。不是在已有工具栏上再加一套侧栏。
- **平板/窄桌面**：按剩余内容宽度使用紧凑 Rail 和工作区面板。不能因浏览器够宽就强制把正文挤成窄列。
- **保存**：三个主页面共用一个动作，桌面在页头、手机可在持续动作区；不与页头保存同时出现。深层详情需要保存当前候选时属于对象动作，不再额外叠全局 FAB。
- **mini player**：有会话才出现，与内容/底栏共同布局，不覆盖正文、保存或手势安全区；没有会话不占空位。

此图是生成的结构参考，不是运行截图。图中来源列表应在手机默认折叠，保存按钮不能照搬为遮挡卡片；工作区打开需要真实遮罩、焦点与关闭行为。样例材料与日期不作事件关联依据；实际数据密度、焦点与动效必须在应用中验收。两案取舍见[整体方案](2026-09-14-product-architecture-review.plan.md)。

### 2.2 语义路由建议

| 语义对象 | 建议地址/落点 | 迁移约束 |
| --- | --- | --- |
| 动态 | 保留 `/home` | 统一变化流，原“事件变化”独立视图改为同流筛选 |
| 资料库 | 保留 `/collection` | 改用户名称，不为改名迁移内容 ID 或所有引用 |
| 内容、编辑、事件 | 保留 `/collection/:id`、`/collection/:id/edit`、`/events/:id` | 页码/媒体时间点参数及真实返回栈保持 |
| 关注 | 新 `/following` | 与可持久关注和增量结果同批上线，不先发布空目的地 |
| 来源与账号 | 新 `/connections`，来源/账号/发送目标在此工作区下钻 | 底层来源与凭据保持独立；第一步可复用现有账号详情 URL |
| 自动任务 | 保留 `/automation` 作为目标工作区 | 现有分发领域/规则 URL 可保留；同步编辑迁至来源详情，旧入口不保留第二套表单 |
| 搜索、Agent、消息、播放器 | 保留 `/search`、`/agent`、`/notifications`、`/player` | 容器按空间变化，语义身份与会话不变 |
| 设置 | 保留 `/settings` 与已使用的分区 query | 不为 URL 美观强制改成全部嵌套路由；实际分区调整时一次迁移 |
| 一次运行 | 保留 `/tasks/:runId` | 各领域唯一完整结果落点，不建第二套任务弹窗 |
| 捕获 | 复用同一 adaptive surface | App/系统分享/Bot 交接统一草稿与保存结果，不要求先回资料库 |

这里是设计路由，不是新 API contract。已有消息、Agent 引用、书签和外部深链需要迁移清单：优先保留对象地址；确有旧链接需求时允许**单向、有限期**重定向并列出移除条件，禁止长期双壳、双表单或按字段猜新旧路径。

## 3. 页面规范

### 3.1 动态：先看变化，不先管理候选

首屏为日期、轻量范围筛选、连续信息流。默认“全部”，可切关注更新/独立内容；稍后处理和已忽略在次级筛选中。没有固定大指标、系统运行时间线或未来功能说明。

- 事件条目显示“发生了什么变化”、所属事件、来源数量/时间和“查看变化”；摘要只说增量，不重复整份综合稿。展开或进入详情才看完整来源。
- 独立条目以标题、短预览、必要封面与来源为主；保存、稍后、忽略属于当前候选的轻量操作。不能把滚过自动当保存，也不要求用户逐项归零。
- 同一次事件更新只占一个主要入口；重复抓取增加来源记录，不刷出新条目。平台收藏导入可合并成批次入口，点击进入资料库对应范围，不把每条已有收藏再当“待收录”。
- 新结果抵达时提示可加载更新，不直接移动用户正在阅读的行。事件更新已读以稳定变化身份记录，不以事件最后更新时间推算。
- 自动化异常不插入普通资讯流；对当前内容不可读的原因在原条目内显示修复入口，系统级待处理事项去消息。

空态区分未连接来源、暂无更新、筛选无结果、来源暂停与请求失败。相应动作是连接来源、查看已有资料、清除筛选、打开来源详情、重试，不用一个“刷新”覆盖所有情况。

### 3.2 资料库：用户拥有的材料，不是任务数据库

默认混合材料采用稳定列表或有可读卡片宽度的网格，手机单列；图集/媒体专属视图才使用画廊。保留当前卡片布局与选择基础，不重新引入默认手机瀑布流。

- 近期保存、稍后阅读、来源集合、整理结果是可解释视图；标签与类型是筛选，不把所有维度并列成多层 Tab。
- 默认范围是用户主动保存或授权收藏同步保留的材料；自动报告可在整理结果和所属事件查看，每个事件默认显示当前结果，旧版本不反复挤入列表。
- 候选因证据引用而被保留，不等于用户已主动收藏；来源生命周期、长期保留理由与用户列表归属分别表达。
- 搜索调用同一个上下文搜索界面，带上资料库范围与当前过滤条件；移除“精确/语义”图标切换的平行查询 UI，不取消底层全文或语义能力。
- 卡片优先标题/主体媒体、来源/作者、阅读长度；最多一条有行动价值的处理状态。不把来源点赞数装成用户操作按钮，不在常规浏览显示相关性分数。
- 长按/显式选择进入批量模式，操作栏替换普通页头；可批量加入事件、设阅读意图、标签或删除，危险影响逐项说明。

外部收藏夹名称与范围必须来自真实平台能力；未提供集合的来源不展示可选集合。外部取消收藏默认保持本地内容，不宣称支持双向管理。

### 3.3 关注：持续目标，而不是事件的另一份列表

关注页列出用户选择持续跟进的事件与问题：标题、最近实质变化、是否有未读变化和简短观察问题。首期只把既有事件做通，不先增加人物图谱、通用项目或任意工作流类型。

- 从内容、搜索或事件详情选择“持续关注”；已有关联事件时优先复用，创建新事件需给明确范围，不能只填一个宽泛标签就自动吸收全库。
- 新建后先选择材料与观察问题，再选择更新方式：站内、定期简报或明确授权的外发。未配置模型时仍可人工组织和阅读，不展示虚假的自动就绪。
- 最近变化是内容增量，不是抓取次数；无变化显示上次有效检查，不制造成功消息。
- 取消关注停止相应持续处理/提醒，不删除事件与归档；事件结束与用户取消关注是两个动作。
- 宽屏可以 list-detail；手机先关注列表后事件详情。辅助 pane 只有证据/待确认关系足够时才出现。

“关注主题/人物/查询”是后续扩展：必须先有稳定范围、精确筛选与误匹配纠正能力；主题查询不自动变成一个事件。

### 3.4 事件详情：变化、综合、证据各有位置

页面顶部为事件标题、关注状态、最近变化与观察问题。主体默认“最新变化”，另外可切完整时间线、材料与证据；事件综合是版本化的解释区，不替代原文列表。

- 变化标明新增事实、来源更正、观点分歧或仅新增材料；未知/未核实不能画成“已确认”。模型文字明确标识，日常不用数值置信度包装真实性。
- 结论旁可定位到原文片段、页码或媒体时间点，并保留版本/生成范围；纯来源链接不能冒充已经保存了原证据。
- 成员保留原阅读模板。综合稿属于 report，原始材料属于 source，观点/背景等角色可读；不把生成稿算为第二个独立证明。
- 人工拒绝关联、修正结论、移除成员都在对应位置完成。自动建议不覆盖已确认字段，也不因为改过标题而永远停止新材料建议。
- 合并/拆分两个已有事件先展示影响并确认，支持恢复关系；删除原材料须说明引用影响，不允许候选清理绕开。

手机默认折叠长来源清单，先看到变化和一个主动作；桌面时间线主列与当前证据辅助栏共享选择状态。返回成员后保留事件位置、选中变化和展开的证据。

### 3.5 来源与账号：在一个任务上下文完成连接

工作区区分“信息来源、平台账号、发送目标”，但不要让用户在三类对象间手工拼装才能开始。常用入口是“连接来源”：

1. 选择 RSS、TG 频道或支持的平台收藏。
2. 需要访问身份才连接/选择账号；公共源跳过。不支持某能力时说明准确范围，不伪造成功。
3. 展示来源范围、采集方式、频率、保留与处理选择；模型/大媒体费用另行显式启用。
4. 预览少量真实可读材料及限制，再启用持续采集。
5. 在原来源行看到首次结果，直接进入动态或资料库；较长工作不阻塞表单关闭。

来源详情拥有范围、同步设置、暂停、最近结果、覆盖/游标进度与恢复。账号详情拥有身份、已保存凭据/实际访问可用/能力受限/需登录、检查和退出；来源与自动任务只引用它，不复制凭据编辑。重新登录后返回原任务位置，而不是账号总览。

发送目标是另一个用途的连接；TG/QQ channel 可同时输入与输出，但开关独立，启用监听不默认授权外发。移除账号说明受影响的解析/同步，不删除已有内容。

### 3.6 自动任务：展示持续目标，不以阶段总览代替产出

首屏为已启用的目标及其最近有用结果，按实际实现提供创建入口，如持续同步收藏、整理关注、定期简报、按规则分发。阶段计数与底层队列为次级诊断，不占首屏。

目标详情的固定顺序：目标与范围 → 期望结果/预览 → 触发和节奏 → 需要的连接/处理能力 → 最近结果 → 运行与诊断。输入/输出未接通时明确阻塞原因与修复入口。

- 同步目标链接到来源详情的唯一编辑器；来源改变立即反映目标状态，不保存第二套频率。
- 规则和复杂目标使用稳定页面，少字段编辑才用 dialog；保存规则不等于启动/立即发送。
- 已成功产物、待索引、待发送、部分失败分别展示；“运行完成”不能暗示平台接受或证据就绪。
- 总暂停、单目标暂停、账号失效含义不同。暂停阻止新工作/外发，不抹去进度，也不默认取消已接受的外部请求。
- 发送队列日期包含非当天日期和完整语义时间；结果未知提供核对入口，不仅“重试全部”。
- 解析、媒体、摘要、索引的全局策略仍有真实控制面，归到处理策略/高级管理；从受影响内容可直达对应阶段，不要求先浏览总览。

### 3.7 内容详情与模板：先消费，再维护

公共部分为返回、来源/作者、标题、可展开摘要、内容主体、相关事件、必要的来源/处理信息和更多动作。短帖标题重复原文时不放大重复；人工标题仍保留。重解析、删除、编辑和原始技术字段不与阅读主动作同权。

| 模板 | 必须保留的语义 | 布局重点 |
| --- | --- | --- |
| 文章 | 标题层级、段落、图文位置、引用/代码 | 限宽正文与按需目录；表格/代码独立横向滚动 |
| 图文笔记 | 图与文字的对应关系、顺序 | 焦点图片/缩略图与正文协调，不把所有攻略压成画廊 |
| 短帖子 | 作者/时间、转发评论、原帖与引用 | 紧凑头部与短正文，不套文章目录 |
| 帖子串 | 节点身份、父子/顺序、不同作者 | 节点化阅读与定位；没有结构时不伪装已解析成串 |
| 图集 | 每项说明、顺序、原图与媒体身份 | 焦点图、沉浸浏览、缩放与翻页；返回保留选择 |
| 对话/消息包 | 发送者、时间、回复/附件、消息边界 | 按消息阅读与引用；不是拼接成 Markdown 长文 |
| 视频 | 资产、章节、字幕、平台 AI 来源 | 画面优先；章节/全文逐字稿分别可读和定位 |
| 音频/播客 | 音轨、章节、逐字稿、Show Notes | 播放控制、队列、书签与阅读，不当普通附件 |
| 文档 | 原文件、页码、文本覆盖、原页/文本关系 | 同一文件/页选择，目录与缩略页按需；扫描无文本不假称已识别 |
| 书签 | URL、保存原因、未解析/轻量保留意图 | 可升级解析，失败可维护，不作所有未知内容的永久兜底 |

这是目标消费语义，不是“十类全完成”清单。串/消息包等必须与后端结构生产和引用一起开发；其他模板优先使用现有真实 reader。

普通详情新增完整来源历史入口，区分原出处、收藏同步集合、分享/转发上下文，不解析 `source` 字符串猜历史。解析候选冲突在头部给一条可定位提示，详细字段比较仍明确确认；长文读到底不是发现冲突的前置条件。

### 3.8 搜索与 Agent：一个输入状态，两种明确行为

- 点击搜索带入当前范围（资料库、事件、来源或全局），范围可见且可解除；URL 保留查询和过滤，返回恢复结果滚动。
- 默认返回可定位原材料与片段，按内容/事件/页码/时间点表达；作者和标签是浏览维度，不伪装知识实体。
- 搜索输入不自动调用 Agent。用户选择“基于这些材料提问”才进入轻量会话；显式显示范围、模型数据去向和将执行的操作。
- 轻量与完整 Agent 工作台共用 session、草稿、确认和引用；展开工作台不复制对话。不把模型回答替换掉原搜索结果。
- 普通工具过程折成可读的一行，失败展开必要信息；参数、原始 JSON、token 用量在技术详情。确认展示影响对象、数据发送范围和风险，不让用户审批晦涩 JSON。
- 键盘弹出或流式回复时保持输入区；会话选择手机抽屉、桌面按需辅助栏。取消必须区分停止生成和已发生的工具副作用。

搜索入口到页面可做容器连续变换，但在统一查询状态完成前不引入新转场引擎。深链接、无来源锚点或减少动效时使用正常路由。

### 3.9 消息、设置、一次运行

**消息**以需要注意/确认、主动任务回执、重要关注变化为主，自动成功记录默认静默。按来源事件/账号/目标去重、支持稍后和移除，点击进入可以完成处理的具体对象；不复制普通 Bot 聊天，也不搬入候选资讯。手机全屏、桌面可侧面板，深链刷新仍可到同一消息。

**设置**收敛为连接与访问、模型与隐私、媒体与存储、通知偏好、外观与系统。来源对象、平台凭据和发送目标迁出后删除旧分区业务实现，不仅藏起标题。复用连续 SettingGroup/SettingTile：短枚举显示右侧当前值，长地址/模型字段展开编辑；能力已配置、测试可用和任务成功分开。

**一次运行**仍由统一任务结果页承担：目标/状态 → 有用结果和对象链接 → 部分失败及可执行动作 → 折叠诊断。重试资格来自后端 typed contract，不从英文错误猜测。结果对象保存失败、模型失败、索引失败、发送未知不能共用“完成”描述。

### 3.10 捕获与持续播放

捕获默认先接收再丰富：收到的链接/附件/文字 → 保存方式与必要成本提示 → 保存结果 → 后续处理。明确规则可直接执行；自然语言不确定时只问一个必要问题。当前严格 Bot 保存前缀不等于开放式意图理解，跨消息附件合并须有单独数据契约。

播放器继续使用一个应用级会话；详情、mini player、展开页和系统控制共享身份与进度。打开新媒体不静默抢播，可立即播放或入队；关闭清除会话，返回只收起。重启恢复默认暂停，签名 URL 不跨重启存储。视频横屏优先画面，手机竖屏控制后为章节/逐字稿，桌面按需媒体—资料双栏。

## 4. 关键任务的完整交接

| 路径 | 默认行为 | 返回/失败应保持 |
| --- | --- | --- |
| 系统分享 → 保存 → 详情 | 不先去首页；保存与后台解析结果分别反馈 | 原附件/说明、待保存队列；保存已成功不得诱导重复上传 |
| 来源 → 登录 → 预览 → 启用 | 只连接必要身份，给真实范围与首批结果 | 来源草稿、选择范围、已导入进度；账号恢复后可续接 |
| 动态 → 事件变化 → 来源正文 | 先变化再证据；原模板阅读 | 流位置、已读变化、事件选择和阅读位置 |
| 资料/搜索 → 持续关注 | 复用已有关联或明确建新事件 | 原搜索范围、所选材料；取消不写半成品关注 |
| 搜索 → 轻量 Agent → 原文 | 显式调用，同一 session，引用精确 | 问题、会话、筛选和结果滚动 |
| 消息 → 账号修复/工具确认 | 到具体对象或会话，不到总览 | 原消息状态、修复对象与任务；确认不可重复执行 |
| 自动任务 → 结果/发送核对 | 产物、执行与外部接受分别表达 | 目标、队列选择、日期范围和核对状态 |
| mini player → 展开 → 返回 | 同一会话，不重新加载另一控制器 | 原页面位置、资产、播放进度与队列 |

返回优先级为临时表面 → 当前对象 → 所属工作区/主分支。直接深链没有来源栈时使用明确所属入口；禁止为了返回而压入第二套 StatefulShellRoute。

## 5. 视觉、动效与响应式规则

### 5.1 层次与密度

沿用现有 Material 3 色彩、字阶、spacing/radius/motion token。页面背景本身就是表面，普通列表不逐行加大卡；来源、任务、设置用连续行，内容与事件才按对象分组。主要依靠文字、留白、tonal surface 区分，不靠一排同色胶囊和大图标底座。

一个区域一个主要动作，其他动作按语义降级；危险操作不能隐藏影响说明。桌面表单与正文限宽，标题与内容对齐共享起点，空辅助栏不占固定空间。图片主色只影响局部媒体区域，不让整页主题随内容剧烈跳变。

不设“一屏只能两张卡”等机械指标。以正常手机能辨认标题、结果、来源与下一步为准；读者不应需要先理解解析状态、Top K 或队列分桶才能阅读。

### 5.2 响应式沿用同一状态

当前统一窗口类别是 `<600 / 600–839 / 840–1199 / 1200–1599 / ≥1600`，高度 `<480` 另判；这些已有实现，不再作为待新建架构。组件读取自身剩余约束，不按设备名称硬编码。

- 手机竖屏单列，常用操作触达稳定；非关键来源、诊断和长摘要渐进展开。
- 正常桌面有分组导航和限宽正文；事件/资料/设置在确有内容时使用 list-detail 或 supporting pane。
- 手机横屏重点验证播放器、输入与底栏高度冲突；平板重点验证单双栏切换与来源表单；桌面缩窗重点验证侧栏占宽后阅读列和焦点。
- 旋转/尺寸变化不重建草稿或选择状态，页面实例和路由语义尽量保持。折叠姿态按真实设备需求验证，不作为本轮设计中心。
- 可访问性保留对比度、语义标签、键盘/触控、合理目标大小及减少动效。大字号与罕见比例不是本轮主优化目标，也不能以此删掉已有保护。

### 5.3 动效解释层级，不制造表演

复用现有 AppMotion：状态约 200ms、内容切换 240ms、表面进入 320ms/退出 200ms、容器 450ms，具体 Material 组件尊重其原生机制；数值是现有设计基线，不是实测帧率承诺。

- 同层切换短而克制；分页、SSE 更新和 provider rebuild 不重播整页入场。
- 设置展开让后续行平滑让位，隐藏编辑区不抢焦点；保存失败保留草稿。
- 卡片到详情仅在来源身份明确时共享稳定锚点，不飞完整业务 Widget；深链/源消失/媒体失败正常降级。
- 播放器只转换承载容器，不同时挂载两个视频节点；PiP 需独立核对真实平台生命周期。
- 标准预测性返回、草稿确认和根弹层作用域保留；先保证取消/提交正确，再追求视觉增强。
- 流体 hover 仅试用于桌面等高导航；与选中态有明确区别，触控使用按压反馈，减少动效直接切状态。

[旧审校的录像](../knowledges/ui-review-2026-09-13/motion.md)证明当时这些交互可展开/关闭，不证明所有设备流畅。后续只在受影响任务上观察快速反向、加载中返回、键盘、播放与减少动效，不堆积无关动画脚本。
