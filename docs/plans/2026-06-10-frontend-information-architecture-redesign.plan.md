# VaultStream 前端信息架构与体验设计方案

## 状态

active

## 文档职责

本文是 VaultStream 前端信息架构、页面职责、布局、自适应行为和动效语言的目标设计规范，也是现有前端重设计专项的实施依据。它描述未来界面应当怎样工作，不代表当前代码已经实现。

本文不定义后端 API 字段、数据库结构、具体 Widget 树或逐文件改造步骤。当前实现事实仍以 `docs/frontend/`、Flutter 代码和可重复验证结果为准。

本文作为前端总体构想与体验设计依据，不设置同名执行记录。实际开发由用户选择具体功能切片；实施进展和验证结果由确有需要的专项 plan/process、issue、提交和当前实现文档承担。

## 一、背景与当前代码基线

VaultStream 已经具备 Material 3、动态颜色、深浅主题、三项主导航、收藏检索、不同内容详情布局、自动化分区、设置 Section Shell 和 Agent 工作台等基础能力。当前主要问题并不是“完全没有设计”，而是局部实现不断叠加后，页面中同时出现过多同权信息、同权按钮和同形状容器，导致用户找不到视觉与操作重点。

当前代码中可以确认的结构性问题如下：

| 领域 | 当前事实 | 设计影响 |
| --- | --- | --- |
| Root Shell | `AppShell` 已收敛为动态、收藏库、自动化三项主导航；通知仍是占位 bottom sheet | 主导航方向正确，但工具入口以浮动 overlay 覆盖所有页面，尚未形成稳定 App Bar 与 adaptive surface |
| 响应式 | `ResponsiveLayout` 主要使用 800、1200 两个断点，部分页面自行判断 900 等宽度 | 页面对手机、平板、桌面和横屏的理解不一致，不能稳定组成 canonical layout |
| 主题 | 已有 `AppSpacing`、`AppRadius`、`AppMotion` 和全局 `ThemeData` | 页面仍大量直接写圆角、颜色、阴影、时长和曲线；全局卡片统一 28 圆角使所有内容看起来同权 |
| 动态 | 当前只显示迁移说明和发现统计 | 首屏在解释“以后会做什么”，没有真正引导用户浏览信息 |
| 收藏库 | 顶栏并列搜索、模式切换、清除、刷新、筛选；默认手机双列瀑布流 | 工具争夺标题空间，卡片高度和视觉密度不稳定，移动端阅读与点击负担过高 |
| 内容详情 | 顶栏并列摘要、重解析、编辑、删除、原文五个图标动作 | 阅读内容不是第一视觉重点；模板只覆盖文章、图集、视频和资料型布局的部分情形 |
| 自动化 | 总览包含说明、四项指标、三张领域卡和异常面板；领域仍在同一页面树内切换 | 信息重复，页面继续承担规则、队列、历史、诊断和复杂弹层编排 |
| 设置 | 已有宽屏分区导航和移动端列表—详情 | 基础方向正确，但分区内部过长，自动化、发现和同步职责仍可能重复 |
| Agent | 宽屏会话列表—对话双栏，窄屏顶部横向会话条 | 工具事件、引用、确认和消息都以相似小容器连续堆叠，重点和过程层级不足 |
| 动效 | `flutter_animate`、`AnimatedSwitcher`、`Hero`、`OpenContainer` 和局部动画并存 | 动效没有统一协议；整页 fade、卡片 hover scale、FAB shimmer 和共享 Hero 容易互相干扰 |

## 二、设计目标与非目标

### 设计目标

1. 用户进入任意页面后，能在数秒内理解这里最重要的内容和下一步动作。
2. 主导航、工具入口、领域页和对象详情各自只承担一个稳定层级。
3. 内容本身优先于系统状态；系统状态可见、可诊断，但不支配日常界面。
4. Material 3 Expressive 用于强化选择、层级、连续性和反馈，不用于增加装饰。
5. 手机竖屏、手机横屏、平板、折叠屏和桌面共享同一语义结构，但采用不同布局。
6. 列表—详情、搜索、通知和播放器拥有连续且可预测的转场，并支持 Android 预测性返回。
7. 关键筛选、选择、阅读位置、播放状态和任务上下文在旋转、断点变化和路由返回后保持。

### 非目标

- 不把这次设计变成一次大规模同时重写所有 Flutter 页面。
- 不恢复已删除的Discovery 或 Review 主入口。
- 不为未实现的后端能力创建可点击占位设置。
- 不用复杂动画掩盖页面职责、数据 contract 或媒体访问问题。
- 不要求所有页面使用相同卡片、相同双栏或相同强调色。
- 不在本文预设富媒体、事件和 Agent 的开发先后顺序。

## 三、界面组织的五个层级

### 第 0 层：连接与初始化

包括服务器连接、首次引导和必要的数据兼容提示。只有在系统不可用或尚未初始化时出现，不与日常主导航并存。

### 第 1 层：Root Shell

只包含三个长期稳定的高频目的地：

- **动态**：现在有什么值得看。
- **收藏库**：保存了什么，怎样找到、查看和使用。
- **自动化**：系统在做什么，哪里需要控制或修复。

### 第 2 层：全局工具与持续会话

这些能力跨页面存在，但不作为新的主导航目的地：

- 统一搜索与指令入口，可由横向搜索框展开，并调用 Agent 完成复杂请求。
- 统一捕获入口，可作为具有明确视觉重点的全局动作。
- 消息盒子/通知中心。
- 独立账号中心。
- Agent 对话与完整工作台入口。
- 设置入口。
- 当前音视频播放会话。

这些工具的最终位置尚未确定。候选形态包括顶栏工具区、各页面共用的侧边栏，以及横屏或宽屏下与导航区域融合的全局侧栏；窄屏也可以考虑通过一致的侧滑入口打开。具体组合需要通过原型比较后确定，不在本文提前固定。

### 第 3 层：Section Shell

用于一个领域内的稳定子任务，例如设置分区、自动化三域、搜索结果类别和 Agent 会话列表。Section 切换必须保留父层级，不能伪装成互不相关的顶层页面。

### 第 4 层：对象详情与临时 Surface

内容、事件、任务、规则、来源、账号、运行和播放详情使用独立详情语义。确认、少量字段编辑、筛选和临时预览才使用 dialog、bottom sheet 或 side sheet。

## 四、页面与路由总表

| 页面或 Surface | 建议语义位置 | 首要任务 | 当前状态 |
| --- | --- | --- | --- |
| 连接 | `/connect` | 建立服务器连接 | 已有，需视觉收敛 |
| 首次引导 | `/onboarding` | 完成必要初始化 | 已有，需缩短和分步 |
| 动态 | `/home` | 浏览经筛选的近期变化 | 已有路由，内容待重建 |
| 收藏库 | `/collection` | 查找、浏览和管理存档 | 已有，需重构工具层和卡片体系 |
| 内容详情 | `/collection/:id` | 阅读、观看、收听或检查一条存档 | 已有，模板和动作层级待重构 |
| 事件详情 | `/events/:id` | 查看跨模板事件进展与证据 | 目标能力，实施前需重新核对范围与依赖 |
| 自动化 | `/automation` | 按领域查看和管理自动化功能及运行状态 | 已有，需移除占用过多空间的指标体系并重整领域入口 |
| 收藏同步 | `/automation/sync` | 管理来源同步与最近运行 | 当前以内嵌 section 存在，目标为稳定领域页 |
| 分发 | `/automation/distribution` | 管理规则、队列和历史 | 当前以内嵌 section 存在，目标为 list-detail |
| 解析与后处理 | `/automation/processing` | 查看处理链、相关对象与索引状态 | 当前主要是健康矩阵，需继续拆分 |
| 任务结果 | `/tasks/:runId` | 查看一次后台运行的统一结果 | 已有，等待 typed renderer contract |
| 消息盒子/通知中心 | `/notifications` 的语义路由 | 集中查看和处理送达的信息、消息与回执 | 当前仅占位；不同断点可呈现为不同 surface |
| 全局搜索与指令 | `/search` | 查找内容，或从同一输入入口调用 Agent | 收藏页已有局部搜索，尚无统一入口 |
| Agent | `/agent` | 延续搜索框发起的会话，或执行完整的跨领域任务 | 已有基础工作台，入口和能力有待继续调整 |
| 账号中心 | `/accounts` | 管理已连接账号、平台身份及其状态 | 新目标能力，不复用此前已删除的旧账号页面 |
| 设置 | `/settings/<section>` | 管理应用和系统配置 | 当前使用 query section，可演进为稳定子路由 |
| 捕获 | `/capture` 的语义 surface | 接收链接、文件、分享和自然语言保存指令 | 已有分享 sheet，需统一捕获语义 |
| 展开播放器 | `/player` 的语义 surface | 管理当前播放、章节、字幕和队列 | 目标能力，尚未实现 |

同一个语义路由可以按断点呈现为全屏页、双栏详情、bottom sheet 或 side sheet，但返回栈和目标对象必须一致。

## 五、全局布局与视觉重点规则

### 5.1 每个首屏只有一个主问题

- 动态首屏回答“现在看什么”。
- 收藏首屏回答“怎样找到并打开内容”。
- 自动化首屏回答“要管理哪一类自动化，当前运行情况如何”。
- 详情首屏回答“这条内容是什么”。
- 设置首屏回答“要修改哪一类配置”。

页面不得使用大面积说明卡解释页面未来会做什么，不得使用大面积的看上去很漂亮的各种统计指标来占用内容。说明只用于空状态、首次使用或功能变化提示，并可关闭。

### 5.2 操作分三级

1. **主操作**：每个区域最多一个，使用明确文字。例如“保存内容”“继续播放”“重新连接”。
2. **次操作**：与当前对象强相关，使用 tonal、outlined 或普通文字动作。
3. **低频操作**：编辑、删除、重新解析、原始数据等进入“更多”菜单或详情子区。

不再在 App Bar 中并列五个以上同权图标。图标只用于返回、搜索、播放、关闭等高度通用动作；业务动作必须有文字、tooltip 或菜单上下文。

### 5.3 Surface 数量与嵌套

- 默认页面背景本身就是一级 surface，不需要把整页再包入大卡片。
- 一个首屏原则上只出现一至两个主要容器；同色卡片不得层层嵌套。
- 卡片用于表达一个可选择对象或稳定语义组，不用于给每段文字加边界。
- 指标只有在能推动决策时出现；纯统计移入详情、筛选结果或诊断页。
- 分隔优先使用留白和 tonal surface，必要时才使用 `outlineVariant`。

### 5.4 视觉 token

| 系统 | 目标规则 |
| --- | --- |
| 色彩 | `surface` 承载阅读；`surfaceContainer*` 表达层级；`primary` 只强调选择和主动作；`tertiary` 用于特殊知识或 Agent 建议；`error` 只用于真实错误和危险动作 |
| 形状 | 普通卡片使用中等圆角；pane 使用较大圆角；sheet/dialog 使用 28 级圆角；按钮和选择指示器可以 pill。不得所有容器统一 28 圆角 |
| 排版 | 页面标题、section 标题、对象标题、正文、辅助信息分别映射到 TextTheme 角色；不在页面随手设置字号和负字距 |
| 间距 | 以 4/8 基础网格形成组件、组和页面三级间距；同级信息间距一致，跨 section 使用明显更大的节奏 |
| 高度 | 主要依靠 tonal surface；阴影只用于菜单、浮层、拖拽和确实覆盖复杂内容的播放器 |
| 动效 | 只使用语义 motion token；避免页面随手选择 duration、curve 或重复调用 `fadeIn`。动效应灵动、稳定、符合直觉，并保持前后衔接。 |

Lexend / Inter 可以继续作为品牌与正文字体候选，但需要验证中文 fallback、离线可用性、字重和文本缩放，不能让网络字体加载决定首屏排版。

## 六、Root Shell 与全局工具

### 6.1 主导航

- Compact：底部 NavigationBar，固定动态、收藏库、自动化三个带文字目的地。
- Medium：窄 NavigationRail，始终显示三个目的地的标签。
- Expanded：继续使用 Rail，而不是因为屏幕变宽就增加入口。
- Large 及以上：可扩展为带品牌和文字的宽 Rail；内容仍受最大宽度约束。

切换主导航时保留各分支的滚动位置、筛选和已选对象。重复点击当前目的地时回到该分支根页面；是否回到顶部由页面显式处理。

### 6.2 顶部工具区

现有覆盖页面内容的 `Positioned` 工具条需要移除，但替代形态尚未固定。顶栏、全局侧边栏、与宽屏导航融合的工具区都属于候选方案，并应遵循以下关系：

- 搜索框同时承载查找和指令输入，可以展开为轻量 Agent 会话。
- 轻量会话必须保存到 Agent session，并能继续展开为完整 Agent 工作台。
- 消息盒子、账号中心、Agent 和设置都需要清楚的显式入口；在采用侧边栏时可组成稳定的全局工具组。
- 窄屏可以使用一致的侧滑入口或精简工具区，宽屏可以利用侧栏或加宽的顶栏，但不能重复放置多套同权入口。
- 工具容器不得覆盖页面主内容；消息数量只显示真实未读或待处理状态。

### 6.3 捕获入口

- 捕获是需要明确视觉重点的全局动作，可以位于顶栏、侧边栏首要位置或窄屏 FAB；最终形态与全局工具布局一同通过原型确定。
- 自动化和深层详情不重复增加第二套捕获入口。
- Android 分享、Bot 和桌面入口直接进入同一捕获流程，不先跳到收藏首页。

### 6.4 持续播放

全局播放器属于 Root Shell 持久层，不属于某个详情页面。没有播放会话时完全隐藏；具体展示位置和收缩形态尚待参考同类应用并通过横竖屏原型确定，但必须避免遮挡导航、正文、捕获入口和系统安全区。

## 七、各界面具体设计

### 7.1 连接与首次引导

#### 功能与布局

- 连接页只包含服务器地址、凭据、连接测试和明确错误，不展示系统设置全集。
- 测试成功后进入必要初始化；失败时保留输入并说明错误类别。
- 引导按“连接 → 必要存储选择 → 完成”拆成少量步骤，非必要模型、Bot、发现源配置延后到设置。

#### 自适应与交互

- Compact 使用单列全屏表单；横屏保持表单可滚动并避让键盘。
- Medium 以上限制表单宽度，剩余空间用于简短产品说明，不增加装饰型插画卡片。
- 返回时不丢失非敏感输入；敏感凭据不得进入路由参数。

### 7.2 动态页

#### 首要任务

尽可能直观的展示说明“发生了什么、有哪些我可能感兴趣的内容、有哪些变化”。

#### 页面结构

1. 简洁标题与日期，不使用大面积欢迎 Hero。
2. 主体为连续信息流，按事件更新、独立内容、批次摘要等稳定形态排列。
3. 每项只显示标题、必要预览、来源/时间和一个轻量主动作；不展示内部评分、“为什么推荐”或额外的可信说明。

#### 交互与跳转

- 独立内容进入 `/collection/:id`。
- 聚合内容进入 `/events/:id`。
- 任务异常进入 `/tasks/:runId` 或对应自动化领域。
- 轻量动作只包含收藏、忽略、稍后阅读和调整来源或主题偏好；复杂编辑进入详情。
- 信息流必须能较清晰的呈现“哪些内容是被合并的”。

#### 自适应

- 极窄 Compact 使用紧凑的网格式内容单元，弱化独立卡片外框并减少间距；宽度增加后逐步切换为边界更明确的卡片形态。
- Medium：保持主阅读列，不为了填满宽度强制双列。
- Expanded：主阅读列加可隐藏 supporting pane，显示关注事件、来源摘要或当前选中项预览。
- Large：主列保持可读宽度，辅助 pane 不超过整体注意力的三分之一。
- 手机横屏：缩短 App Bar，隐藏非关键摘要，避免顶部栏、播放器和底栏同时挤压内容。


### 7.3 收藏库

#### 首要任务

快速搜索、筛选并打开已经保存的内容。

#### 页面结构

1. 标题和统一搜索入口。
2. 一行可横向滚动的已生效筛选摘要；高级筛选不常驻占据首屏。
3. 内容区。
4. 选择模式使用上下文工具栏替换普通标题，不再额外浮出一套重复控制。

搜索模式不再用“脑形图标/搜索图标”让用户猜测。搜索面板使用文字说明“精确与全文”“语义相关”，默认混合返回，只有需要时才展开高级范围和 Top K 等技术选项。搜索详细界面需要从页面上的搜索框连续展开，而不是从页面中间凭空出现另一个搜索框。


#### 内容布局

- 默认不使用瀑布流。混合内容采用稳定列表或等节奏 adaptive grid，保证阅读顺序和视觉基线。
- 极窄 Compact 使用紧凑网格，弱化卡片容器和间距；稍宽的 Compact 再切换为具有独立边界的卡片布局。
- Medium 为两列；Expanded 为二至三列；Large 为三至四列，并设置卡片最小/最大可读宽度。
- 只有用户筛选“图集”或主动切换到媒体浏览模式时，才允许使用 masonry / gallery 布局。
- 卡片按文章、图文笔记、短帖子、帖子串、图集、对话、视频、音频、文档和书签形成不同信息结构，但共享来源、状态和选择语义。

#### 卡片重点

- 第一层：代表媒体或内容类型、标题。
- 第二层：作者/来源、发布时间、阅读或播放长度。
- 第三层：一条可选的状态，例如“字幕可用”“待重新解析”。
- 语义命中原因只在搜索结果中显示，不在普通浏览永久占位。
- hover 只改变 tonal surface ，不再整体放大 1.03；不得周期性 shimmer。

#### 交互与跳转

- 点击卡片进入内容详情；长按或显式选择按钮进入批量模式。
- 筛选：Compact 使用接近全高的 bottom sheet；Expanded 使用 side sheet。
- 新增内容进入统一捕获 surface。
- 路由 query 是筛选的可分享内容；页面返回后恢复筛选、滚动和选择，不在离开页面时无条件清空。

### 7.4 内容详情与模板

#### 公共结构

所有模板共享：返回、来源证据、标题、作者/时间、收藏状态、原文入口、关联事件、必要处理状态和“更多”动作。公共结构不意味着所有内容使用同一个万能详情页。


#### 模板布局

| 模板 | 核心布局 | Expanded supporting pane |
| --- | --- | --- |
| 文章 | 可读宽度正文、目录、引用、代码和阅读进度 | 目录、来源、关联内容 |
| 图文笔记 | 文字与对应图片交错，支持步骤、地点或对象分组 | 目录、地图/对象索引、来源 |
| 短帖子 | 紧凑作者头、正文、引用/转发关系和媒体 | 原帖、转发评论、相关讨论 |
| 帖子串 | 有明确节点边界的纵向串，保留父子/顺序 | 串目录、作者和来源变化 |
| 图集 | 焦点图，单项说明和原图信息 | 缩略图导航、媒体信息 |
| 对话/消息包 | 按发送者、时间、回复和附件组织 | 参与者、检索结果、引用定位 |
| 视频 | 播放器、章节、字幕和简介 | 字幕/章节、资料、队列 |
| 音频/播客 | 封面、主控制、章节、逐字稿、Show Notes | 队列、书签、时间点笔记 |
| 文档 | 页面预览、页码、目录和文本层 | 缩略页、目录、引用详情 |
| 书签 | URL、保存原因、轻量摘要和升级解析入口 | 来源状态和相关内容 |

#### 自适应

- Compact：按顺序形成内容流；次要信息使用可展开 section 或 bottom sheet。
- Medium：只在内容确实需要时出现 supporting pane，不强制所有模板双栏。
- Expanded 以上：文章/文档限制正文宽度；图集、视频和对话可使用主内容—辅助信息双栏。
- 手机视频横屏优先播放器，控制和字幕使用可收起层；折叠屏 tabletop 将媒体与控制分置铰链两侧。
- 旋转和断点变化保持阅读位置、媒体页、章节、字幕选择和播放进度。

内容封面主色只影响顶部媒体区域、选择状态或局部 container，不重新给整个详情页生成一套强烈主题，避免跨内容切换时视觉跳变。

### 7.5 事件详情

事件是跨模板的组织视图，不替代成员内容模板。

#### 页面结构

1. 标题、关注状态、最近变化和简短综合。
2. “只看变化 / 完整时间线 / 观点与证据”相关视图。
3. 关键进展时间线，默认隐藏纯重复抓取。
4. 已确认事实、未确认信息、冲突观点分别表达。
5. 成员内容以文章、帖子、图集、视频等原模板预览出现。
6. 关联历史事件、人物、主题和下一步观察问题。

#### 交互与自适应

- 点击成员进入对应内容详情，返回保持事件位置。
- 合并、拆分、纠正关系是明确可撤销动作。
- Compact 单列；Expanded 使用时间线主 pane 与证据/关系 supporting pane。
- Agent 更新必须逐条引用，并以增量变化形式出现，不能覆盖人工修订。

### 7.6 自动化

#### 总览

首屏不设置独立的“需要处理”区域，也不以异常处置作为页面主角。运行问题应归入收藏同步、分发、解析与后处理三个所属领域，在相应入口或详情中显示；由于前端通常只能提供查看详情和重试，异常能力保持轻量即可。

统计信息应压缩或收折，不占据主要空间。总览只保留三个领域入口，以及当前选中领域必要的运行概况和最近活动。

#### 收藏同步领域

- 来源列表、启用状态、上次同步和下一次时间等信息。
- 当前运行与最近失败。
- 预览、同步、恢复等动作必须遵守统一策略。
- 运行详情统一进入 `/tasks/:runId`，不再弹出完整 metadata/result。

#### 分发领域

- Expanded 使用规则列表—规则详情/队列的 list-detail。
- Compact 先显示规则列表，进入规则后再看匹配队列；推送历史是同领域的独立 section。
- 新建和编辑复杂规则使用独立详情或全屏 surface；只修改名称、开关等少数字段才使用 dialog。
- 外部发送前的审批状态必须清晰，保存规则不等于立即推送。

#### 解析与后处理领域

- 按解析、媒体归档、摘要/OCR/转写、全文/语义索引分组。
- 以处理阶段、最近运行和相关内容为主；少量异常在所属阶段内联显示，并提供查看详情或重试。
- 平台账号问题跳转账号中心；任务结果跳转统一任务页，不另建复杂故障处置工作台。

#### 路由与状态

领域和选中对象进入真实路由，而不是只保存在 `AutomationPage` 的本地 enum。这样深链接、刷新、预测性返回和桌面多 pane 才能使用同一状态。

### 7.7 消息盒子/通知中心

这一界面以收件箱或消息盒子的形式集中承接系统通知、任务回执、Bot / Agent 消息与确认请求，不与动态页混合。

#### 消息类别

- 需要及时查看的信息。
- Bot / Agent 消息和等待确认的请求。
- 用户主动任务的完成回执。
- 账号、权限或运行状态变化。
- 周期摘要。
- 只记录、不主动打扰的静默消息。

#### 信息结构

顶部提供简洁的分类和状态筛选，下方是按时间与会话关系组织的消息列表。

每条消息只显示发生了什么、何时发生、关联对象和一个主要动作。完整配置、日志和重试参数跳转到对应的任务、账号中心、自动化或 Agent 页面。

消息支持分组、去重、全部已读、单条静默、稍后提醒和过期。高频运行更新必须合并，不能每个进度事件都生成一条新消息。

#### 自适应

- Compact：全屏消息盒子，遵守系统返回手势。
- Medium：可使用 modal sheet 或较宽 dialog，视高度决定。
- Expanded：可使用右侧 side sheet 或全局侧栏中的展开面板；主页面保持上下文，但不可同时操作被遮挡区域。
- 深链接统一使用 `/notifications` 语义，关闭后返回真实来源页。

Bot 转发后的待确认消息跳转 Agent 或捕获确认，不在消息列表中内嵌完整对话。

### 7.8 全局搜索

搜索框是统一的查找与指令入口。普通查询直接展示内容结果；复杂问题或操作指令可以在搜索框展开后的界面中调用 Agent，而不要求一开始就进入完整工作台。

#### 搜索与指令视图

1. 搜索输入与历史/建议。
2. 普通查询展示内容、事件、人物/主题和音视频时间点等结构化结果。
3. 全文、精确和语义筛选使用清楚文字表达。
4. Agent 请求在同一展开界面中形成轻量对话或任务状态。
5. 由搜索框发起的 Agent 交互保存为正式 session，并可继续展开为完整 Agent 工作台。

#### 自适应与跳转

- 搜索详细界面需要从页面上的搜索框连续展开，而不是从页面中间凭空出现另一个搜索框。
- Compact：搜索框展开为全屏 search / Agent surface。
- Medium/Expanded：先扩展为较宽 surface；普通搜索可进入稳定 `/search` 结果页，Agent 请求则保持会话连续并可展开工作台。
- 点击内容、事件或时间点进入相应详情；返回恢复查询、筛选、滚动或当前会话。

### 7.9 Agent 工作台

Agent 是受控工作区，不进入三个主导航目的地，但在全局侧边栏或其他工具区域保留独立、显式的对话入口。搜索框发起的 Agent 请求与这里使用同一套 session。

#### 页面结构

- 会话选择。
- 当前会话对话流。
- 可折叠的工具过程。
- 证据与引用。
- 高风险动作的确认组件。
- 固定输入区和取消/停止状态等配置信息。

普通工具调用默认折叠为一行状态，失败或用户主动展开时才显示参数和结果。引用以可定位的内容卡或 supporting pane 展示，不连续堆叠大量 chip。确认 surface 使用明确风险、影响对象、预计成本和确认/拒绝动作，不直接展示难懂的原始 JSON。

#### 自适应

- Compact：会话列表进入抽屉或独立页面，不占用固定 92 高度横向 chip 条；对话全屏。
- Medium：会话 rail 可收起；对话为主。
- Expanded：会话列表、对话、证据/运行 supporting pane 组成最多三 pane，但第三 pane 只在有证据或工具时出现。
- 键盘弹出、旋转和流式响应不得使输入区或当前消息跳动。

### 7.10 账号中心

账号中心独立管理已连接账号、平台身份、登录状态、权限和平台能力，不再隐藏在设置的长列表中。新的账号中心按照当前产品需求重新设计，不恢复此前已删除页面的旧结构。

- 账号列表清楚区分“已保存凭据”“连接可用”“权限受限”和“需要重新登录”等状态。
- 连接、检测、解绑和修复进入账号对象详情；自动化运行和历史仍回到对应领域。
- Compact 使用账号列表到详情的单页下钻；Medium/Expanded 使用 list-detail。
- 账号中心作为全局工具提供显式入口，具体位于顶栏还是侧边栏随 Root Shell 原型确定。

### 7.11 设置

设置只管理应用和系统配置，不重复管理账号对象。主要包括 AI 与发现、推送与通知、外观、存储及系统等配置，最终分组可在实现时继续收敛。

- Compact：分区列表 → 全屏分区 → 必要时进入具体配置详情。
- Medium/Expanded：稳定 list-detail，左侧分区，右侧限制宽度的设置内容。
- 普通设置使用连续 section 和分隔留白，不给每个字段单独套卡片。
- 高级参数默认折叠，并说明改变它的实际影响。
- 自动化运行、消息历史和账号状态不复制进设置。

### 7.12 任务结果

任务页是所有后台 run 的唯一完整结果落点。

页面结构为：任务摘要、当前状态/时间线、关联对象、业务化结果 section、允许动作、诊断信息。原始 metadata/result 默认折叠到“详情”。

- 从动态、通知、自动化和内容详情进入同一 run 时，展示一致。
- 可执行动作来自稳定 task renderer contract，前端不根据字符串猜测重试。
- Compact 使用单列；Expanded 可以用摘要—结果双栏，但不把 JSON 与用户结果并列为同权内容。

### 7.13 统一捕获与分享确认

捕获 surface 接收链接、文字、图片、文件、音视频、转发关系和自然语言指令。

页面顺序为：收到的内容 → Agent/规则理解结果 → 建议模板和保留策略 → 必要确认 → 保存进度。明确指令直接执行；模板、合并对象或存储成本不确定时只提出一个关键问题。

- Compact 使用接近全屏的 bottom sheet 或全屏 route，避让键盘和系统手势。
- Expanded 使用居中 dialog 或 side sheet，预览与指令可以双栏。
- 保存后返回来源应用或当前页面，并通过通知展示长任务结果。
- 捕获进度不阻塞 UI，也不把后台解析细节全部暴露在确认面板。

### 7.14 全局音视频播放器

- 音频与视频详情共享同一播放 session、进度、章节和队列。
- 离开详情后收缩为 mini player；返回详情重新展开同一 session。
- 视频可切换仅听声音，或进入应用内 mini player / 系统画中画。
- mini player 的最终位置不预先固定；可以位于底部持续区域或宽屏 supporting pane，但必须与导航、侧栏和正文协调，不遮挡内容。
- 展开播放器根据宽高切换：竖屏以封面/画面和控制为主，横屏以媒体为主，桌面使用媒体—字幕/章节双栏。
- Android 原生媒体通知、锁屏、耳机按键、音频焦点和后台恢复属于同一能力验收。

## 八、跨页面交互与返回关系

| 来源 | 动作 | 目标 | 返回后应恢复 |
| --- | --- | --- | --- |
| 动态 | 打开独立内容 | 内容详情 | 动态位置、已读和理由状态 |
| 动态 | 打开聚合更新 | 事件详情 | 动态位置和展开状态 |
| 收藏库 | 打开卡片 | 内容详情 | 查询、筛选、滚动、选择模式 |
| 收藏库 | 高级筛选 | bottom/side sheet | 当前结果保持，确认后增量刷新 |
| 通知 | 处理任务异常 | 任务或自动化领域 | 通知已读、原分组和滚动 |
| 消息盒子 | Bot/Agent 待确认 | 捕获或 Agent | 消息状态与对话上下文 |
| 搜索 | 打开结果 | 内容/事件/时间点 | 查询、筛选和滚动 |
| 内容详情 | 查看任务 | 任务结果 | 阅读位置和处理状态 |
| 自动化 | 打开规则/运行 | 规则详情/任务结果 | 领域、选中规则和队列筛选 |
| mini player | 展开 | 播放器/媒体详情 | 原页面状态不变，播放不中断 |

返回层级遵循“临时 surface → 对象详情 → section → root”。关闭按钮只用于临时 surface；页面使用系统返回。Android 预测性返回必须预览真实目标，不用透明路由或重复 Hero 阻断手势。

## 九、自适应 UI 规范

### 9.1 统一窗口类别

| 类别 | 宽度 | Root 导航 | 内容策略 |
| --- | --- | --- | --- |
| Compact | `< 600dp` | Bottom Navigation | 单 pane、全屏详情、bottom sheet |
| Medium | `600–839dp` | NavigationRail | 单 pane 或窄 list-detail，部分 modal surface |
| Expanded | `840–1199dp` | Rail / 可扩展 Rail | 标准 list-detail 或 supporting pane |
| Large | `1200–1599dp` | Extended Rail | 两至三 pane，正文和表单限宽 |
| Extra large | `>= 1600dp` | Extended Rail | 受限主内容加稳定辅助 pane，不无限拉伸 |

`ResponsiveLayout` 应成为唯一窗口类别来源，逐步删除页面自行使用 800/900/1200 的判断。组件响应自身可用宽度，但不能另建与窗口类别冲突的全局断点。

### 9.2 高度、方向和姿态

- 方向不是简单的 `width > 800`。布局同时考虑宽度、高度、系统栏、键盘和显示铰链。
- 手机横屏高度不足时缩短 App Bar、隐藏非关键辅助信息，并避免 bottom nav、播放器和输入区三层叠加。
- 折叠屏 book posture 将 list/detail 分置两侧；tabletop posture 将媒体与控制分置上下两侧。
- 交互元素不得跨越铰链或被 display cutout 遮挡。

### 9.3 输入方式

- 所有触控目标至少约 48dp，文本缩放后不重叠。
- 桌面提供 hover、右键上下文、键盘焦点和快捷键，但不能把 hover 作为唯一发现方式。
- 搜索、Agent、表单和媒体控制支持合理 Tab 顺序与键盘操作。
- 拖拽和 pane 调宽属于增强能力，核心任务不依赖它们。

## 十、动效、衔接与形变规范

### 10.1 总原则

- 动效首先解释对象身份、空间关系、层级变化和操作结果。
- Shell、导航、播放器和搜索等持续对象应保持或持久化，不在每次路由中重新入场。
- 同一时刻只有一个主运动；列表、标题、背景和按钮不能分别播放无关动画。
- 前进和返回分别设计；返回通常更短、更克制。
- 所有动效都提供减少动效降级。

### 10.2 语义 motion 类型

| 类型 | 用途 | 建议节奏 |
| --- | --- | --- |
| 状态变化 | 选中、展开、按钮形变、进度完成 | 150–250ms，standard |
| 临时 surface 进入 | menu、dialog、bottom/side sheet | 进入约 300–400ms，退出约 180–250ms |
| 同层内容切换 | section、筛选结果、list-detail 选择 | 200–300ms，轻微 fade/位移 |
| 容器转换 | 卡片到详情、搜索框到搜索页、mini player 到完整播放器 | 400–550ms，emphasized |
| 预测性返回 | 详情回列表、全屏 surface 回来源 | 跟随手势进度，完成阶段约 250–400ms |

具体实现统一引用 `AppMotion` 的语义 token，不在页面直接写时长和曲线。

### 10.3 收藏卡片到详情

1. 点击后冻结被选卡片，立即取消 hover 和缩放，列表保留占位。
2. 只共享卡片外壳和稳定视觉锚点，不让带网络请求、Riverpod watch 和完整业务内容的卡片作为 flight shuttle。
3. 前 60% 将容器位置、尺寸、圆角和局部 tonal color 变换到详情入口 surface。
4. 封面可用时在容器内部连续变化；封面失败或缺失时使用固定 fallback，不让错误占位参与飞行。
5. 正文、侧栏和维护动作在容器接近展开后再渐入，不能与飞行卡片同时叠在首屏。
6. 返回时先淡出详情辅助内容，再收回容器；源卡片不存在时降级为普通 fade/scale。

详情背景必须始终是不透明 `surface`。当前“整卡片 Hero + 透明详情层 + 多个详情 Hero”的路径应先移除，再重新建立单一 shared container 协议。

### 10.4 搜索形变

- 用户点击全局搜索时，当前输入入口连续扩展为搜索或轻量 Agent view；输入焦点、已输入文字和光标保持。
- Compact 形变到全屏；Expanded 先扩展为较宽 surface，再根据意图展示搜索结果或 Agent 会话。
- Agent 交互保存 session，并可在不丢失上下文的情况下继续展开完整工作台。
- 只在被点击的搜索入口和目标输入之间建立共享身份，其他页面搜索框默认不参与。

### 10.5 通知与 sheet

- Compact 通知从顶部工具入口展开为全屏 surface，圆角逐步归零并支持预测性返回。
- Expanded 通知从右侧进入 side sheet，背景只做轻微 scrim，不缩放整个主页面。
- 通知项已读、合并和移除使用局部尺寸/透明度变化，不整页重新 fade。

### 10.6 播放器形变

- mini player、媒体详情和全屏播放器是同一持续对象，不创建第二个播放器实例。
- 展开时共享封面/画面、标题和播放进度；控制组根据空间重排，而不是整体截图缩放。
- 视频进入画中画或仅音频时，播放进度和队列保持，形变只表达载体变化。

### 10.7 页面和列表动效限制

- Root 分支切换只做低干扰 cross-fade 或短 shared-axis，不重复播放整个页面 `fadeIn`。
- 列表分页、SSE 刷新和 provider rebuild 不触发整页入场。
- 禁止周期性 FAB shimmer、所有卡片依次飞入、hover 大幅 scale 和无目的弹性回弹。
- skeleton 只用于真实等待，不和内容同时显示；完成后采用短交叉淡化。

### 10.8 共享转场协调

建立一个统一的共享转场协调层，记录来源对象、目标语义、前进/返回方向和降级方式。默认禁止未被选中的重复卡片、图片或标题参与共享转场；目标不存在、深链接进入或返回源被过滤时，主动降级，避免残影和重复 Hero。

## 十一、性能、可访问性与状态

### 性能

- 长列表分页、虚拟化和图片低成本预览；默认网格不为测量瀑布流高度反复布局。
- 不在 shared transition 中触发网络请求或重新监听 provider。
- 图片、字幕、转写和详情 supporting pane 延迟加载，但主要内容先稳定占位。
- SSE 更新只刷新受影响对象，不让整个自动化或详情页重建并重新播放动画。
- 全局播放器、搜索状态和长任务不依附单个页面生命周期。

### 可访问性

- 正文普通文本满足对比度要求，状态不能只依赖颜色。
- 图标按钮具有语义标签；业务动作优先显示文字。
- 支持 TalkBack、键盘焦点、200% 文本缩放和减少动效。
- 触控目标、焦点顺序和错误提示在所有断点一致。
- 图片、视频、音频和文档提供替代信息；模型生成描述明确标记。

### 状态恢复

必须恢复：Root 分支、section、搜索查询、筛选、列表位置、选中对象、阅读位置、媒体页、播放 session、Agent 会话和未完成输入。临时提示和过期 shimmer 不需要恢复。

## 十三、实施方式

本文描述完整目标，但不规定固定开发顺序。每次由用户选择一个页面、用户任务或跨端能力作为功能切片，并遵守以下约束：

1. 开始前核对当前 Flutter 代码、相关后端 contract、现状文档和 issue，确认问题仍然存在。
2. 只实现该切片完成用户任务所必需的结构、视觉、交互、后端和数据变化。
3. 同一切片内删除被替代的旧入口、旧组件和旧状态路径，不保留长期双实现。
4. 在手机竖屏、横屏、平板和桌面等相关断点完成验证，并记录未验证项。
5. 完成后更新当前实现文档和 issue；需要继续跨会话推进时，再为该切片建立或更新专项 plan/process。

## 十四、验收标准

### 信息架构

- 主导航始终只有动态、收藏库、自动化。
- 每个用户职责只有一个主入口；消息盒子、账号中心、任务、设置和 Agent 不复制彼此的完整业务页。
- 动态、收藏、自动化、账号中心、设置、任务和 Agent 的首要任务能在首屏明确识别。

### 视觉与重点

- 首屏不存在大面积未来说明、无行动价值指标或三层同色卡片嵌套。
- App Bar 不出现五个以上同权图标动作。
- 极窄屏使用紧凑网格式内容单元，宽度增加后切换为卡片；普通混合内容不默认使用瀑布流。
- 页面直接写颜色、圆角、阴影、断点、时长和曲线的数量持续下降。

### 自适应

- 至少验证 360×800、800×360、600、840、1200 和 1600 宽度，以及一个折叠屏 posture。
- Compact、Medium、Expanded、Large 和 Extra large 使用同一语义状态。
- 旋转与断点变化后保留筛选、选择、阅读和播放状态。
- 超宽屏正文、表单和对话不会无限拉伸。

### 动效与返回

- 卡片到详情只出现一套共享视觉，不存在残影、重复图片或正文重叠。
- 深链接、无封面、图片失败和返回源卡片不存在时能够稳定降级。
- 通知、搜索和播放器在 Compact/Expanded 使用相符的形变和返回关系。
- Android 预测性返回、系统返回、关闭临时 surface 的语义一致。
- 减少动效开启后不依赖位移和形变理解功能。

### 可用性与性能

- 浅色、深色、动态色和高文本缩放下层级仍清晰。
- TalkBack、键盘、鼠标和触控均能完成核心路径。
- 核心列表滚动、媒体播放、SSE 更新和转场无明显掉帧或整页重建闪烁。
- Flutter analyze、相关 widget/unit test 和多断点截图验收结果被记录；未执行项明确标注。

## 主要风险

- 信息架构、视觉和路由同时大改会扩大回归面，必须按垂直切片推进。
- 内容模板设计依赖内容模型与真实样本，不能只凭静态 mock 确认。
- Flutter 当前 Material 3 Expressive 能力并不与 Compose 完全一致，形变和 motion 需要在现有 SDK 上原型验证。
- 共享转场、预测性返回、播放器和折叠屏必须在真实设备或可靠模拟器验收，静态代码无法证明体验正确。
- 如果继续保留旧弹层、旧 Hero 和旧 provider 作为 fallback，新设计会再次形成双重界面和职责污染。
