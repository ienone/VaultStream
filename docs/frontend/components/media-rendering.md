# 媒体渲染与图片访问

## 文档状态

active

## 当前代码

- 统一媒体 DTO：`frontend/lib/core/media/media_asset.dart`
- 候选执行器：`frontend/lib/core/media/media_source_session.dart`
- 图片组件：`frontend/lib/core/widgets/network_thumbnail.dart`
- 后端媒体接口：`backend/app/routers/media.py`

## 当前职责

- 卡片按后端返回的资产顺序选择代表图片；卡片用途下，后端会把有本地变体的图片排在仅远端的封面之前。
- 图片组件按后端顺序逐一请求候选，去除空 URL 和重复 URL；当前候选加载或解码失败后才切换下一项。
- 详情封面、头像、正文图片、媒体网格和全屏图集已贯通同一候选列表；Markdown 中与 `MediaSource` 精确匹配的原图 URL 会还原为该资产的完整候选顺序。
- 视频和音频播放器按相同的候选状态机初始化，当前来源初始化失败后才尝试下一项。
- 资产来源不再在组件边界丢成裸 URL：图片、全屏图集、正文嵌套图片、卡片和队列预览持有资产/变体身份。签名过期或 410 时每个资产只自动刷新一次 manifest；403 直接进入授权失败，404 本地来源上报服务端核验后再降级。
- 音视频会先读取 `purpose=playback` 的候选；初始化失败或播放中断时串行切换下一来源，运行期切源恢复已知进度。签名媒体请求不携带全局 API Token。
- 详情主体音视频和图集内嵌视频共用应用级 `GlobalPlaybackController`；独立 Chewie 执行器与依赖已删除。图集浏览只展示播放选择，用户点击才接管现有会话。同一控制器在详情离开后继续存在，Root Shell 仅在有会话时显示 mini player；展开 `/player` 不重新创建媒体控制器。音频始终使用有限阅读宽度的单列；视频在 Compact 使用单列，足够宽高时使用媒体/会话信息双栏。
- 播放队列属于同一个播放会话，不复用自动化分发队列。已有媒体播放时打开另一条音视频详情不会静默抢播，而是提供“立即播放”和“加入队列”；`/player` 可播放、移除和拖动排序待播项，当前媒体正常结束时自动续播下一条。当前媒体、位置、队列、倍速和仅听声音偏好写入本地会话快照；应用重启后以暂停状态恢复，并按媒体资产 ID 重新读取播放 manifest，不持久化资产签名 URL。关闭播放器会清空运行会话、队列和快照。
- `/player` 的播放设置直接作用于同一媒体控制器：支持 0.75x、1x、1.25x、1.5x、2x 倍速，并可设置 15、30、60 分钟后暂停。视频可切换为仅听声音：只隐藏画面，不创建第二个控制器，也不改变当前位置、章节、队列或书签；该会话偏好会沿用到后续视频。倍速同样沿用到队列中的下一项；定时器在会话内切换媒体时继续生效，关闭播放器时取消。
- 带持久媒体资产的播放会话可读取和创建时间点书签。书签使用后端独立 `media_bookmarks` contract，记录明确内容、资产、毫秒位置和可选笔记；列表点击回到同一播放会话的准确位置，编辑与删除不改写解析得到的章节/逐字稿。
- 内容详情和 `/player` 读取同一播放请求携带的 `media_segments`。列表按当前资产过滤；章节与逐字稿同时存在时通过分段控件切换，各自按时间排序、独立高亮并可 seek，不再以章节覆盖逐字稿。只有一种时直接展示该类型。
- 文档和其他附件展示后端返回的原文件名、MIME 与大小；打开已知过期的本地签名来源前会按资产刷新一次 detail manifest，失败后才尝试下一候选。没有 OCR 结果时不把摘要或说明伪装成文档正文。
- 签名本地媒体、后端代理和允许直连的原图候选均不携带全局 API Token。
- `mapUrl()`、`mapPlayableUrl()`、图片专用鉴权头及其运行时调用方已经删除；前端不再把 `local://`、存储键或任意远端地址自行改写成媒体请求。
- 动态发现卡片、`rich_payload` 引用/子项图片和自动化队列封面已接入内容 `media_assets` 的有序候选；缺少匹配资产时显示占位或省略媒体，不读取旧字段直连。
- 详情媒体网格的翻页、缩略图选择和网格形状使用共享 `AppMotion` / `AppShape`；选中缩略图以尺寸、语义色边框和 tonal surface 表达，不再添加装饰性阴影。媒体页码与视频占位使用 inverse surface 颜色和 TextTheme 角色，深浅主题不依赖固定黑白文案样式。
- 详情骨架与收藏列表骨架共用低干扰 pulse 节奏并尊重系统减少动效；全屏图集工具栏使用同一 shape 和 TextTheme 层级。

## 不承担职责

- 前端不应默认把所有外链都强制代理。
- 图片渲染不应阻塞在后端转码和本地缓存上。
- 失败态不应掩盖具体原因。

## 状态与输入输出

- 新输入：后端排好序的 `MediaSource[]`、媒体大小、图片尺寸和 fit 参数。
- 输出：一个活动媒体请求和同会话待播队列；单项失败时切换下一候选，全部失败后显示带稳定原因和手动重试的语义占位。
- 副作用：读取资源级签名或允许直连来源；仅 manifest 刷新和本地缺失核验进入已鉴权控制面。

## 响应式和失败态要求

- 桌面：缩略图、详情头图和媒体网格应保持稳定尺寸，不因加载失败改变页面层级。
- 移动：图片失败态不应挤压正文或遮挡操作按钮。
- 加载：显示低干扰 loading 占位。
- 空状态：空 URL 不请求网络，直接返回空占位或不渲染。
- 错误状态：按 HTTP 状态与来源类型区分签名过期、授权无效、本地缺失、远端不可达和格式不支持；不解析错误文案。

## 尚未实现 / 计划扩展

- 图片 HTTP 失败已具备稳定分类；部分平台的原生音视频插件不会暴露 HTTP 状态，因此真实设备上的 410/404 分类仍需运行验收，不能由初始化测试外推。
- 分发消息已从统一资产/变体选择平台可用来源，Telegram/NapCat 不再读取旧 archive metadata/`cover_url`；真实 Telegram/QQ 媒体发送仍待授权环境验收。
- 后端签名 blob 的 Range、播放器运行期切源/进度恢复、应用内全局播放会话、重启后暂停恢复、同会话播放队列、倍速、定时停止、仅听声音、持久时间点书签，以及章节与逐字稿分别切换、定位的导航已有实现；当前长期回归保留签名/Range 访问和播放器暂停恢复，其余按变更专项验收。当前解析/摘要流程仍不生产这些时间段。睡眠定时器是当次运行状态，不跨重启恢复；仅听声音当前复用视频流并隐藏画面，不代表服务器已选择低带宽音轨；逐字稿正文来自经过校验的时间片段，不等于字幕轨渲染。真实 Chrome 已验证音视频解码、页面返回与浏览器历史返回继续播放、跨内容不抢播、队列自动续播，以及刷新后暂停恢复；继续播放时保留 1.5 倍速。Web 导航开始时保留播放意图，转场结束、视图移除后恢复同一控制器，明确暂停与定时停止优先；长媒体连续播放、定时暂停、原生后台生命周期、系统媒体会话/PiP/媒体控制和字幕轨仍未人工验收或实现。
