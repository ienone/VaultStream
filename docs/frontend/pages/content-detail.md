# 内容详情页

## 文档状态

active

## 当前代码

- 页面：`frontend/lib/features/collection/content_detail_page.dart`
- 路由：`/collection/:id`

## 用户任务与当前界面

用户在这里阅读一条存档，查看来源、作者、正文、媒体、标签和统计，并执行编辑、删除、重新解析或打开原文等内容级动作。来源行在后端提供作者头像时显示小尺寸圆形头像，并沿用统一媒体源优先级与鉴权头；缺失头像时直接省略，不显示无意义占位。

详情头按“平台与内容类型 → 标题 → 作者身份与时间”分层，不把所有元信息挤在同一横排。宽屏时作者、来源与时间进入右侧信息栏，窄屏时才回到标题下方；顶栏是唯一的原文入口。知乎回答把关联问题标题与问题统计合并进详情头，不再在正文前重复渲染关联问题卡。宽屏目录使用独立的低层级背景容器，与正文和其他辅助信息形成区分。文章向下阅读越过标题后，右侧栏以平滑停靠状态显示当前文章标题。

详情根据内容的有效布局与平台内容类型选择文章、图文笔记、短帖子、图集、视频、音频、聚合页、主页或书签结构。宽屏下，图文笔记、带媒体的短帖子、图集和带主页媒体的账号主页采用沉浸式媒体阅读器：左侧媒体占据主舞台，右侧按“平台 → 作者与时间 → 标题与正文 → 统计 → 标签”组织内容，不再叠加第三列辅助栏。多图媒体保留底部缩略图条；鼠标进入媒体区后显示悬浮左右切换按钮，页码、缩略图和按钮使用与全屏媒体工具栏一致的玻璃表面。纯文字短帖使用紧凑正文卡片，标题与正文重复时不再单独放大标题；引用内容区分作者、正文与原文动作。失败时应保留替代信息和重试/原文路径。详情页不展示处理流水线，摘要、索引、归档、评分和分发等运行状态统一归入自动化与任务页。

加载时优先保持从列表传入的内容上下文；详情头在共享容器内延续已知标题与来源，正文和宽屏辅助栏使用与最终布局一致的骨架。加载失败、内容被删除和媒体失败均有独立状态。

卡片进入详情时只共享一套不透明容器，直接展开到详情头的真实位置；飞行层在卡片快照与详情头之间交叉过渡，正文和辅助栏在后半段渐入。沉浸式媒体模板从加载首帧起就建立与最终页面一致的左媒体、右内容双栏，唯一 Hero 的几何目标是右栏真实标题头，而不是双栏外框的左上角；左侧媒体舞台独立显现，右侧其余内容随后淡入并轻微横移。短帖的列表缩略图可能只是链接预览，不能单独证明详情会采用沉浸式双栏；只有结构化媒体资产或明确封面存在时，短帖加载态才把共享标题目标放到右栏，否则保持普通阅读流的左侧标题目标。返回使用更短的收拢时长。详情正文和媒体不建立第二套 Hero；深链接、来源卡片不存在或系统减少动效时使用普通页面转场。

## 自适应行为

- 窄屏使用单一阅读流，媒体、元信息和正文按阅读顺序排列。
- 宽屏只在内容适合时使用阅读区与上下文区并列，不强制所有模板双栏。
- 小红书等图文笔记以及带媒体的短帖、图集和账号主页在宽屏使用整页左媒体、右内容的沉浸式双栏；空间不足时退回纵向阅读流。
- 横竖屏切换应保留阅读位置和当前媒体页。

## 承担职责

- 单条内容的阅读、媒体浏览和人工维护。
- 展示来源证据与已生成的内容摘要。
- 发起内容级后台动作并链接其运行结果。

## 不承担职责

- 不承担全局自动化诊断、账号修复或长期任务归档。
- 不展示或操作后台处理流水线；相关诊断和动作归入自动化与任务页。
