# 设置页

## 文档状态

active

## 当前代码

- 页面：`frontend/lib/features/settings/settings_page.dart`
- 路由：`/settings`

## 用户任务与当前界面

设置按连接与访问、AI 模型、信息来源、推送与通知、推送目标、媒体与存储、外观与系统七个分区组织。对应深链参数为 `connection`、`automation`、`sources`、`push`、`targets`、`storage`、`system`。AI 模型先展示配置，能力诊断在其后折叠；信息来源先展示来源对象，再展示发现策略。旧分区别名已删除，生产入口使用上述键。

收藏同步的策略、预览、执行和记录只在 `/automation/sync`。解析、摘要和索引开关在 `/automation/processing` 对应阶段；分发模式在分发页；Cookie 保活在账号列表。设置不再复制这些控制面。

平台账号健康、扫码连接、检测、解绑和 Bilibili 手动凭据已迁入独立 `/accounts`，设置不再重复管理账号对象。连接与访问分区只负责后端 API 地址、VaultStream 访问密钥、服务器连通性和网络代理。

设置项包含普通编辑、开关、枚举、敏感凭证、连通性测试和需要确认的重置/退出动作。模型“已配置”、健康检查和真实连通性测试必须分别表达。

自动化处理页提供真实的“自动语义索引”开关：关闭后后端在内容入库/解析的 post-ingest 阶段停止创建索引任务和调用 embedding provider；它不删除已有索引，也不禁用用户显式发起的手动重建。

“内容理解/摘要”只在自动化处理页提供一个开关并写入 `enable_auto_summary`；“内容生成”区只配置摘要模型，不再重复展示同一个开关。关闭后 post-ingest 跳过自动摘要，内容详情中的用户显式生成动作仍保持独立。

RAG 索引状态中的失败项重试通过设置领域的 typed action provider 发起，页面不再直接拼装语义重建请求或解析动态 `run_id`。

自动化处理页提供真实的“解析队列处理”开关：关闭后解析 worker 不再领取后续任务，但用户仍可捕获内容并将任务留在 pending 队列；重新开启后继续处理。已经进入执行中的任务不会被该开关强制中断。

存储设置中的“自动归档远程媒体”及图片、视频子开关同样直接约束后端处理入口；质量、数量和视频体积限制会传给实际归档处理器。关闭只影响后续归档，不删除已有本地媒体，也不强制中断已经开始的下载。

“Cookie 保活”开关约束每一次计划中的平台检查，而不只是应用启动时决定是否创建任务。关闭后不再访问平台或生成保活结果/账号通知；重新开启无需重启后端，在下一调度点恢复。已经开始的检查不会被强制中断。

分发模式选择“暂停”后，后端会停止新的自动审批、规则刷新产生的自动审批、入队、worker 消费和 Agent 批量推送；规则失效时仍允许把旧的自动审批撤回待审，人工审核不受影响。

推送与通知分区提供应用内周期摘要开关、6 小时/12 小时/每日/每周间隔和立即生成入口。立即生成调用真实摘要 API，并明确区分“已创建摘要”和“本周期没有新变化”；它不把确定性活动汇总描述成 AI 总结。

Bot 配置保存、Telegram 服务控制和群组同步由设置领域的 typed action provider 发起（群组管理独立在推送目标分区）；页面不直接拼 endpoint、payload 或动态响应字段。后端外部进程/网络动作已进入可注入 service，并通过 typed 结果携带运行类型、run ID、状态与错误；配置已保存和 Bot 已在线仍分别表达。

## 自适应行为

- 页面按自身可用区域的统一窗口宽度/高度类别布局；`expanded` 以上且高度不紧凑时，同时显示分区 supporting pane 和当前分区。
- `compact` / `medium` 以及短横屏先选择分区，再进入全屏分区内容；返回时回到分区列表。
- 宽屏左侧为带返回按钮的分区列表，右侧是一块包含标题与正文的连续表面；正文居中限宽。没有中间竖线、内层圆角框和重复的“设置分区”标题。分区列表只显示名称与识别图标；手机列表保留范围说明。
- 表单限制阅读宽度，低频高级参数默认折叠。来源短表单按内容收缩，不强制手机全屏或桌面固定高度；共享表面负责整表滚动，短横屏和键盘压缩空间时仍能滚动到操作区，切换尺寸保留输入。标题不要求装饰图标。
- 分区导航使用普通列表项，保留名称与简短范围说明；取消逐项装饰卡片、图标底座和分区标题的重复说明，不为填满屏幕放大导航。

分区切换更新当前设置地址而不清除进入前的路由；窄屏返回先回设置列表，再回来源页面。选中分区内容在单双栏切换时保留同一个子树；桌面已经显示的默认分区在缩窄后也继续显示详情。短横屏顶栏压缩为 48dp，正文避让侧边与底部安全区。

推送凭证与权限使用可折叠的直接表单：平台、凭证、超级管理员、白名单和黑名单，再保存。移除 Stepper 和未接入保存的独立 Telegram 管理员输入框；实际管理员仍通过原有 `*_admin_ids` 配置保存。Bot Token 输入遮蔽显示。停止的 Telegram 使用普通状态文字，按运行状态显示启动或停止/重启，不将“未运行”猜成“未配置”；QQ 连接失败不伪装为在线，状态读取失败可重试。桌面设置表面使用 Material，避免遮挡列表水波纹。推送目标空态与读取失败不套卡片，失败可重试。

## 视觉语义

- 分区与内容依靠单一表面色差表达层级；右侧仅保留外侧圆角。设置组不包边框或背景卡片，弹层保持独立操作语义。
- 设置组以标题和分隔线组织，不逐组套卡或增加入场动画；普通开关与标签同行，仅长操作显式另起一行。图标与说明均为可选。高级参数沿用 Material 展开交互。
- 具体业务状态使用 `ColorScheme` 语义色，设置 Shell 不固定浅色或深色值。
- 普通设置工具页使用标准 Material 3 tonal AppBar；二维码区域保留黑白对比，不把毛玻璃或品牌固定色当作通用状态语义。

## 承担职责

- 全局、低频、用户可控的配置。
- 能力状态和真实测试入口。

## 不承担职责

- 不展示完整运行历史或复杂收藏同步工作流。
- 不管理外部平台账号对象或登录会话。
- 不暴露后端尚未实现的策略占位。
- 不把自动化领域操作复制到设置中。

## API 关联

- 领域：`../../backend/api/agent-system-events.md`、`../../backend/api/automation-delivery.md`
