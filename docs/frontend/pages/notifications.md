## 用户任务与当前界面

消息盒子集中展示持久化任务回执与需要注意的失败，不再把后台 diagnostics 临时拼成无语义地址的 bottom sheet。页面顶部按消息类别和状态筛选；消息以连续列表呈现，展示发生了什么、时间、合并次数和详情入口。任务失败展示任务名、可用的内容标识和简短原因；原始 SQL、校验数据保留在诊断详情。旧消息通过关联的运行记录使用同一展示规则。未读以文字强调、状态点及轻量底色区分，需要注意的失败保留图标。没有详情地址的消息展示完整正文；全部记录中的已移除消息显式标注，操作菜单可恢复。

用户可以全部已读，也可对单条消息标记已读/未读、静默、稍后提醒、移除或从全部记录中恢复。所有状态写回后端。入口以小圆点提示真实未读状态，具体未读数由工具提示、可访问名称和手机菜单文字提供，避免大字号数字覆盖图标或标题；菜单数量实时跟随同一数据源。SSE 是刷新提示，Web 在页面被使用时保留低频轮询兜底。

当前后端生产后台失败、用户主动任务完成回执、Agent 工具确认、Telegram Bot 显式捕获成功回执、平台账号登录失效和周期摘要消息。待确认消息跳转所属 `/agent?session_id=...` 会话，决定完成或所属运行/会话取消后不再出现在活动消息中；Telegram Bot `/ai` 发起的确认保留 Bot 来源，也可在原 Bot 消息通过归属受控的按钮决定。`/save` 的链接、文字和附件只有在内容提交成功后才产生“捕获回执”，可按类别筛选并跳转 `/collection/:id`；删除内容后回执自动移出。账号提醒跳转 `/accounts`，由手动检测、扫码登录、主动退出和 Cookie 保活的真实结果驱动；未配置不提醒，同一连续失效不重复刷屏，恢复后自动移出。周期摘要只汇总持久化动态和事件变化，空窗口不生成占位消息。普通 Bot 对话仍不作为消息生产者。

## 自适应行为

- 消息整个页面属于应用侧栏的正文工作区；打开后保留侧栏并高亮“消息”，不再压入覆盖侧栏的全窗页面。
- 手机、短横屏和窄窗口使用单栏正文，导航入口打开应用抽屉，底栏保留三个主入口且不将消息误标为其中一项，筛选控件随宽度及字号自动换行，列表保持单列。
- 宽屏左侧消息列表、右侧详情，点击任务在原位展开结果，保存回执可在右侧阅读内容；不弹出独立任务页。窄屏切到详情，返回恢复列表位置。普通消息展示正文，账号与 Agent 消息提供明确的领域入口。
- 筛选、列表、加载、空态和错误使用同一滚动区域；空态按实际剩余高度居中，短屏能滚动到错误重试。页面支持下拉刷新，修改筛选回顶部，进入详情再返回保留原位置。
- 类别与状态复用搜索页的共享选择菜单，名称和当前值清晰区分。筛选和消息操作均使用根 Navigator 的主题圆角菜单，覆盖应用级播放器；短屏可滚动到末项，支持键盘与系统返回，尊重减少动画。

## 不承担职责

- 不内嵌完整任务日志、账号修复表单或 Agent 对话。
- 不根据自由文本猜测重试、确认或外部发送动作。

消息筛选区与列表使用一致的居中阅读范围。加载中或读取失败时不开放“全部标为已读”；HTTP 错误没有业务响应体时保留状态码，便于区分服务拒绝与状态更新失败。

消息按后端 offset / limit 分页，每页 100 项；切换筛选返回第一页。未选择消息时列表使用完整可读宽度，选中后才打开详情栏。任务失败列表项保留标题和状态，原始诊断在任务详情查看；其他有效摘要仍显示。

任务消息读取时关联现存内容标题，列表不展示内部内容编号；失败消息正文仅显示可用的内容标题，错误留在任务详情。消息操作响应与列表复用同一展示投影，旧消息无需回填。
