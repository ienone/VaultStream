# 全局搜索页

## 文档状态

active

分组内采用可点击的列表行和分隔线，不为每条命中重复套卡片。搜索结果只展示有命中的分组；指定类型没有结果时直接显示无结果状态，不用其他类型或多张空分组补位。没有搜索历史时保留搜索输入区，历史词来自用户实际查询。

## 用户任务

用户从 Root Shell 的全局工具入口搜索已经持久化的内容与人工知识事件，并从结果进入原始内容或事件详情。复杂问题可以把当前查询交给 Agent 工作台继续处理。

## 当前实现

- 路由为 `/search`，稳定参数包括 `q`、`kind` 和 `content_scope`。
- `kind` 支持全部、内容、事件、人物、主题和时间点；`content_scope` 约束内容及由内容派生的人物、主题、时间点结果，支持收藏库、发现和全部内容。
- 内容结果读取 `GET /search/unified` 中的混合语义检索结果，展示标题及可用的作者、摘要；不展示内部平台代码或检索算法标签。
- 知识事件只按事件标题、描述、成员备注和成员内容的标题、摘要、正文匹配；不把词法匹配伪装成向量检索，也不在正常首屏堆放检索实现说明。
- 人物由混合检索命中及 `author_name` 精确召回的内容聚合，主题由混合检索命中及 `tags` 精确召回的内容聚合；直接查作者或标签不依赖 embedding。点击后分别以稳定 `author` / `tag` 参数进入收藏库筛选，不创建虚构人物或主题实体。
- 音视频时间点只读取带 `segment_type`、`media_asset_id`、`start_seconds` 的章节或转写切片。后端会核验媒体资产属于命中内容、类型为音频或视频且秒数未越过已知时长；发布日期不会被当作时间点。
- 内容进入 `/collection/:id`，事件进入 `/events/:id`。时间点进入 `/collection/:id?t=...&media_asset=...`，详情页选择对应媒体资产并把显式秒数交给应用级播放器。
- “交给 Agent”把查询预填到 `/agent?prompt=...`。Agent controller 会建立或恢复正式 session，但不会在用户再次确认发送前自动调用模型。
- 空查询在输入区下方展示与收藏库共用的本地搜索历史；执行查询后同步浏览器 URL 并收起键盘。清除按钮同时清除查询和旧结果，保留类型与范围。无结果和错误状态可在短屏中滚动。
- 结果列表的滚动控制属于 `/search` 页面本身。进入内容、事件或媒体时间点详情后按系统返回，会恢复原查询、结果类型、内容范围和像素位置，不重新请求同一结果；真正修改查询或筛选时回到新结果顶部。

## 响应式行为

- Compact / Medium 使用单列结果流；六种结果类型使用可见下拉选择，三种内容范围同行呈现，不靠横向滑动发现隐藏类别。
- 结果区自身可用宽高达到 Expanded supporting-pane 条件且有多个非空分组时，“全部”类型以两列排列结果；单一分组使用单列。
- 页面按真实结果、目标类型和返回流程做浏览器专项验收；原有按文案/布局断言的 widget 套件已删除。

## 不承担职责

- 不生成答案或综合事件。
- 不把人物或主题聚合伪装成独立实体。
- 不从发布日期、媒体总时长或模型猜测生成时间点；没有显式带时间的章节/转写切片就返回空结果。
- 不自动执行 Agent 请求或任何有副作用的工具。
- 不替代收藏库内面向当前列表的筛选和批量操作。

## 尚未完成

- 当前解析与摘要流程尚不生产转写/章节时间字段，因此真实存量数据只有在其他受控流程已写入上述切片 contract 时才会出现时间点结果。
- 搜索建议目前只有历史记录，没有后端建议或意图分类。
- 搜索框到结果页的共享容器形变、真实 embedding 质量和跨端辅助技术仍未验收；滚动恢复曾通过路由 push/pop 验收，后续变更按需复验；真实浏览器历史手势和原生系统返回尚未人工验收。
