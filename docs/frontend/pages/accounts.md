# 账号中心

## 文档状态

active

## 当前代码

- 页面：`frontend/lib/features/accounts/account_center_page.dart`
- 详情：`frontend/lib/features/accounts/account_detail_page.dart`
- 平台账号面板：`frontend/lib/features/settings/presentation/tabs/connection_tab.dart`
- 路由：`/accounts`、`/accounts/:platform`

## 用户任务与当前界面

账号中心集中展示后端 `platform-health` 返回的平台账号状态。用户可以区分未保存凭据、已保存登录、登录失效、同步未启用和同步认证失败；每个平台行明确进入详情，由详情统一提供扫码连接、重新登录、有效性检测和清除本地登录的动作。列表不再逐项重复这些按钮和确认弹层。Bilibili 的手动凭据只保留一个低频展开入口，说明与字段名称完整换行。

点击平台账号进入独立详情。详情只展示 `platform-health` 明确返回的本地登录信息、浏览器登录支持、收藏同步支持/启用/可用/认证状态、当前问题和最近同步；不把这些能力字段包装成平台未声明的 OAuth 权限。最近同步可进入统一任务结果，账号动作继续复用 browser-auth 控制层。

账号列表提供 Cookie 保活策略；

账号中心不读取浏览器 Cookie 或密码；二维码会话、轮询、取消和凭据保存均复用后端 browser-auth contract。清除登录不会修改外部平台账号。

## 自适应行为

- Compact：平台名称与最小状态纵向排列，以箭头表示进入详情；移除重复分界线及内外不同底色。详情使用单一可滚动信息流，账号动作按可用宽度换行。
- Medium/Expanded：列表与详情保持适宜阅读宽度。详情使用限宽单列，按状态与问题、账号操作和修复指南、能力与最近同步排列。顶栏保留平台名称，正文不重复平台标题或同一问题，也不为状态和最近同步额外叠加背景板。能力信息在窄屏／大字号下改为上下排列并保持左对齐；修复步骤使用可换行的编号文本，纵向展开并尊重减少动画。
- 列表到详情使用独立语义路由，返回保持账号中心上下文。
- 扫码对话框复用自适应表单，保留一致的标题、正文边距和主次操作。二维码按内容宽度及短屏高度缩放，空间足够时与状态并排；短高度操作随正文滚动。减少动画模式直接更新内容，不启动尺寸动画。取消、系统返回和初始化响应晚于关闭时均清理服务端会话；轮询读取失败后重试同一会话，过期或初始化失败才新建。

## 承担职责

- 已连接平台身份、登录状态、同步认证摘要和修复动作。
- 平台登录会话和手动平台凭据的用户控制面。

## 不承担职责

- 不管理服务器地址、VaultStream API 密钥或网络代理；这些属于设置。
- 不展示收藏同步、发现或分发的完整运行历史。
- 不把“已保存凭据”解释为“真实业务调用已通过”。

## API 关联

- `GET /api/v1/platform-health`
- `/api/v1/browser-auth/*`
- 平台敏感设置沿用现有 settings contract，不进入日志或 URL query。

## 尚未实现 / 计划扩展

- 真实平台登录与失效恢复仍需要具备对应账号时人工验收。
- 后端当前没有返回平台细粒度 OAuth scope，因此详情只展示真实能力状态，不虚构 scope 清单。

Bilibili 手动凭据复用共享展开区，收起后保留当前页面草稿并禁止隐藏输入获得焦点；主题变化不覆盖未保存内容。凭据遮蔽显示，关闭键盘联想和自动更正，原有配置键与提交路径保留。

## X 网页登录

X 详情提供“保存网页登录”，使用遮蔽输入的对话框保存 auth_token/ct0 到现有敏感设置，不读取浏览器配置、不回填已保存密钥。保存后可执行有效性检测或清除；没有二维码登录。书签和已登录推文解析共用这份会话，挑战或失效会停止读取。API 调试日志关闭请求与响应正文，避免通用 settings 的 value 字段暴露凭据。

## Telegram 用户账号同步

`/accounts/telegram` 独立于 Bot 配置，使用原生账号状态、开关与同步接口。频道动态开关仅同步加入且开启通知的频道；收藏夹开关将 Saved Messages 保存到收藏库。立即同步进入统一任务结果。页面不把会话文件存在显示成已登录；未配置时暂不可手动同步，已配置应用凭据时可从“连接账号”打开二维码及两步验证弹窗。

布局沿用限宽单列，两项开关说明自然换行，按钮按内容宽度排列。开关写入期间禁止重复操作，成功后重新读取持久配置。关闭任一同步项会等待当前批次取消，后续按新设置运行。

Telegram 登录弹窗复用 AdaptiveFormDialog。扫码说明与二维码随可用宽度／短屏缩放，验证码状态按后端 contract 轮询；两步验证使用遮蔽输入。关闭、系统返回或初始化迟到响应均取消对应服务端登录。过期需用户点击重新扫码，暂时读取失败继续查询同一会话，不自动重复创建登录。
