# 来源与账号

## 文档状态

active

## 用户任务与入口

来源工作区的订阅、账号、同步页签分别位于 `/sources`、`/accounts`、`/sources/sync`，保持同一个页面状态。`/accounts` 集中展示平台账号，详情使用 `/accounts/:platform`。添加和编辑订阅使用 `/sources?edit=new`、`/sources?edit=ID`。每个平台在同一可滚动页面内完成连接、同步和对应平台配置；服务器地址、VaultStream API 密钥与网络代理仍属于设置。

页签首次进入时才创建和加载，已访问页签保留滚动与表单状态，隐藏页签暂停动画。订阅来源使用按可视区域构建的列表，不一次展开所有来源组件。

- Telegram：个人账号连接、频道动态与 Saved Messages 同步开关、立即同步，以及 Telegram Bot 状态、凭证权限、群组与频道管理。
- QQ：Bot 连接状态、Napcat 凭证权限、群组与推送目标管理。
- Bilibili、知乎、小红书、微博、X 等：账号状态、连接／更新登录、检测和清除登录、收藏同步开关、同步预览与执行、最近同步结果。Bilibili 手动凭据位于自身详情。

账号操作与同步控制不再要求跳到自动化页面才能完成。来源工作区的收藏同步页保留全平台执行、全局策略和运行历史，平台行链接至账号详情。设置的通知分区保留应用内摘要及账号入口，Bot 配置仅在所属账号页编辑；推送工作区的目标页签是跨平台目标视图，与账号页复用同一实现。

## 界面与自适应

来源、账号与对象详情复用同一列表/详情工作区。宽度足够时列表收折到左侧，右侧编辑来源或查看账号；窄屏只显示当前对象，返回恢复列表和筛选。从收藏同步进入平台详情时保留同步页作为左侧上下文，返回仍到收藏同步。短横屏按可用宽度决定是否并排，两侧分别滚动，不因高度不足强制另开页面。来源草稿跨宽窄屏保留，保存、删除失败留在表单内。

来源类型和同步状态按实际文字及字号计算所需宽度，能容纳时同排；不足时才换行；宽屏把搜索、筛选和添加并排为一行，菜单限制到适合选择的宽度。

单一阅读列按个人账号、同步、机器人及目标分组，低频凭证默认折叠。账号详情最大宽度为 720dp，连接、更新登录和立即同步按内容宽度并排、空间不足时换行，不将单个动作拉满正文宽度。账号列表使用一致的图标和文字边距；等待平台状态时仅显示紧凑进度指示，不套大块闪烁占位卡；次要账号操作使用具名菜单。页面与展开内容一起滚动，不固定底部操作区；横竖屏切换不重建表单。

## 状态与操作边界

- 停用收藏同步的平台不会执行同步侧登录检查，其默认 `authenticated=false` 不作为未登录提示；账号连接状态仍由平台健康控制。
- 平台健康来自 `GET /platform-health`，只展示明确返回的登录与同步事实，不推断 OAuth scope。
- Telegram `session_present` 只表示已保存会话，不声明刚刚在线验证成功。应用凭据未配置时明确显示未配置，连接与同步按钮不可用。
- 扫码登录复用原有自适应对话框及 browser-auth／telegram-account 控制层。取消及迟到响应仍清理登录会话；暂时读取失败继续轮询同一会话，不自动重复创建。
- X 通过遮蔽输入保存网页登录；Bilibili 手动凭据关闭键盘联想。凭据不写入 URL 或日志。
- 同步成功受理后进入统一任务结果；配置已保存、任务已受理、账号已连接和实际同步成功分别表达。
- 清除本地登录不会修改外部平台账号。真实平台登录、同步和发送仍需对应账号验收。

Telegram 原生频道的来源开关显示有效接收状态：Telegram 通知关闭时显示关闭并禁用手动同步，保留应用内原有启用偏好；恢复 Telegram 通知后仍由该偏好决定是否接收。

订阅来源使用紧凑条目，名称最多两行，类型和频率归入元信息，同步与启用排列在条目右侧；点击名称区域编辑。筛选与保留折叠项不再叠加大块上下留白。
