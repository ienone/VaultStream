# 前端文档总览

## 文档状态

active

前端代码位于 `frontend/lib/`，使用 Flutter、Riverpod 和 GoRouter。当前 Root Shell 主入口为动态、收藏库和自动化；设置、任务结果和 Agent 属于工具或深层工作区。

## 页面索引

- `pages/dashboard.md`：近期发现候选、收录操作和进行中事件变化。
- `pages/collection.md`：收藏内容浏览、搜索、筛选和批量维护。
- `pages/content-detail.md`：单条内容阅读、媒体和后处理状态。
- `pages/automation.md`：收藏同步、分发、解析/后处理三类自动化。
- `pages/accounts.md`：独立平台账号状态、连接、检测和解绑控制面。
- `pages/settings.md`：全局低频应用与系统配置，不重复管理平台账号。
- `pages/agent.md`：受控 Agent 会话、工具过程与确认。
- `pages/tasks.md`：后台运行结果统一详情。
- `pages/notifications.md`：持久化消息、筛选和用户消息状态。
- `pages/events.md`：跨模板事件时间线、证据状态和人工关系维护。
- `pages/search.md`：跨内容与人工知识事件的全局搜索及 Agent 查询交接。

## 组件与导航

- `navigation.md`：主导航、工具入口和深链接。
- `components/navigation-shell.md`：Root/Section/Detail 导航容器。
- `components/media-rendering.md`：媒体访问、展示与失败态。
- `components/task-result.md`：任务结果表达边界。
- `components/capture-surface.md`：应用内与系统分享共用的捕获流程。

## 页面文档口径

页面文档服务于职责判断、交互审查和回归验收，不充当 Widget 树的文字镜像。每份页面文档只记录：

- 用户来这里完成什么任务，以及明确不承担什么。
- 首屏主要区域、关键动作和重要状态。
- 手机、横屏、平板和桌面的结构性差异。
- 会打开哪些有独立语义的详情页、dialog 或 bottom sheet。
- 读取/写入哪些 API 领域，以及后台任务如何反馈。
- 已确认问题及对应 issue。

以下内容通常不写：具体 Widget 类名、flex 数值、像素宽度、provider 清单、装饰动画参数和内部私有组件名。只有它们构成稳定 contract 或已确认问题根因时才例外记录。

## 当前约束

1. 一个用户职责只能有一个主入口。
2. 不把未实现策略暴露为设置项。
3. UI 不直接散落 API 写操作；由统一控制层编排。
4. 复杂工作流使用独立页面或明确的 adaptive surface。
5. 当前事实与未来计划分开；未来设计进入 `docs/plans/`。

常态界面不展示调试入口、内部实现说明或原始 JSON。空白不要求填满：空播放队列和无命中的搜索分组不占位，空 Agent 会话与无历史的搜索页保留输入区即可。必要的失败原因、删除影响和下一步操作继续显示；用量、工具参数和任务原始数据放在用户主动展开的详情中。

## 当前重点

- 动态页已接入 discovery 候选流与按更新时间排列的进行中事件，并贯通收录、忽略、稍后处理、恢复及事件详情；自动聚类与事件综合仍未完成。
- 自动化三域已形成；总览只保留领域入口，解析/后处理已按解析、媒体归档、摘要/OCR/转写和全文/语义索引展示真实状态，分发规则新建与编辑已有独立稳定路由。
- 收藏库在主分支切换时保留查询、筛选和列表分支状态；显式重置同时清除输入框与 provider。
- Root Shell 主导航只保留动态、收藏库、自动化；手机竖屏使用底栏，宽度达到 medium 使用窄侧栏，短横屏省略文字标签。保存及工具移入三个主页的页头；设置宽屏为分区列表与单一连续内容表面。原生端与辅助技术仍需单独验收。
- 收藏详情 shared container 已完成历史整改；统一媒体候选已覆盖正文嵌套内容、全屏图集、自动化队列预览和音视频播放器，后端分发也已消费资产/变体。音视频详情现把控制器交给应用级播放会话，离开详情后由 Root Shell mini player 保持进度并可进入 `/player`；详情与展开页共享后端校验后的章节/逐字稿导航，两类同时存在时可分别切换，点击条目定位同一会话。另一条媒体详情不会静默抢播，可选择立即播放或加入同一内存队列；展开页支持顺序、移除、拖动排序、播完续播、0.75x–2x 倍速、15/30/60 分钟定时停止、视频仅听声音，以及带可选笔记的持久时间点书签。仅听声音保留同一媒体身份、位置、章节、队列和书签，不另建播放路径。过期 manifest 单次刷新、本地缺失核验和播放切源位置恢复已有实现；当前长期媒体回归只覆盖暂停恢复，其余按变更专项验收。真实长媒体与自动续播/定时暂停、时间段生产、字幕轨、原生后台播放/PiP/媒体控制及 Telegram/QQ 媒体发送仍未人工验收。
- 平台账号主流程已迁入 `/accounts`，并通过 `/accounts/:platform` 展示后端明确返回的能力状态、问题、最近同步与修复步骤；设置仅保留服务器连接和应用/系统配置。真实平台人工验收与未声明的细粒度 scope 仍不外推。
- `/notifications` 已承接持久化任务失败、用户主动任务回执、Agent 工具确认、Telegram Bot `/save` 捕获成功回执、平台登录失效和基于持久化活动的周期摘要，并支持真实未读、去重、静默、稍后和移除状态；确认可深链并恢复所属会话，Bot 捕获回执可跳转对应收藏且随内容删除自动移出，账号提醒可跳转账号中心且随恢复自动移出。周期摘要可在设置中启用、调整间隔或立即生成；普通 Bot 对话仍不入盒。
- 捕获 surface 已统一应用内链接、原始文本、本地文件和系统分享；同一次分享的多媒体保留为一个内容对象。Telegram Bot 显式 `/save` 及私聊中的明确自然语言保存前缀已复用同一链接、文本和附件 API；普通聊天不会自动归档。跨消息 media group 合并、开放式意图理解、Bot 不确定场景确认和 OCR/转写仍是后续能力。
- `/search` 已成为全局工具入口，按真实 contract 分组展示内容、人工知识事件、命中内容的人物/主题聚合，以及带显式资产与秒数的音视频章节/转写时间点；时间点可进入对应详情并定位同一全局播放器。进入结果详情再返回会恢复查询、筛选和结果滚动位置，修改查询或筛选则回到顶部。转写/章节生产、共享容器形变和完整 RAG 仍未完成。
- Agent 的 `search_content` 已复用同一搜索事实，引用可分别进入内容、人工事件和媒体时间点；工具结果随会话持久化，刷新后仍恢复为结构化引用。真实模型选择工具、逐条引用质量和 supporting pane 尚未人工验收。
