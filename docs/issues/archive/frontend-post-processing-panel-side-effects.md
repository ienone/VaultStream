# 内容详情后处理面板直接执行跨模块写操作

## 状态

resolved

## 原问题

内容详情页曾在正文侧栏展示完整“处理状态”面板。该面板读取摘要、语义索引、媒体归档、巡逻评分和分发阶段，并在详情页直接暴露生成、重建、重试和重新匹配等跨模块动作。诊断信息与阅读内容争夺空间，且页面职责跨越收藏阅读、自动化诊断和任务运行三个领域。

## 处置说明

2026-07-27 已从内容详情页及其共享支撑区删除处理状态面板，同时删除对应 widget 和组件测试。详情页不再请求或展示处理流水线，也不再提供阶段动作；摘要作为已经生成的内容信息仍可展示，后台运行状态和操作统一归入自动化与任务页。

保留后端 processing-status contract 和领域模型，不把“详情页不展示”误解为删除后台处理能力。

## 验证

- `ContentDetailPage` 的窄屏和宽屏布局均不再构造 `PostProcessingStatusPanel`。
- 详情页 widget 测试明确断言不出现“处理状态”。
- 内置浏览器在文章详情宽屏布局下确认右侧仅保留目录和内容统计，不再出现处理阶段卡片。
- `flutter analyze` 通过，定向详情页 widget 测试通过。
