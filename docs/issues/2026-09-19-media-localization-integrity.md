# 图片归档与缓存残留问题

状态：后端归档主链已收敛，仍有下列边界待处理。当前实现见[媒体模块](../backend/modules/media.md)。

## 已处理

- 图片/视频共用下载和成功发布流程；解码或写入失败不重下，写入失败不发布 local 引用。
- 同键并发使用独立临时文件原子发布；同批相同 URL 复用处理结果。
- 再次处理会检查主文件存在性，缺失时重下；缺失缩略图从本地主文件重建。
- URL 保留原有百分号编码；正文替换匹配完整地址，避免破坏签名或误替换 URL 前缀。
- 删除图像 FFmpeg/Pillow 双路径和重复主色实现。Pillow 编码、缩略图和主色放入线程。
- 比较实际字节数，只保存较小的一个主文件；已有 WebP 不重复有损编码。小图直接复用主文件供列表使用。
- 解析与发现共用引用更新，保留部分归档失败或未启用归档的其他媒体。
- 删除 stored_images/stored_videos 重复列表，以及各平台生产、提取、引用与资产入库中的双路读取；状态计数直接来自原条目。旧数据通过 Alembic revision 一次合并，保留来源、角色、存储键和缩略图信息。
- 资产变体采用实际存储 MIME/尺寸/大小/校验和；缩略图不继承主图的元数据。

## 待处理

1. **自动补齐入口。** 已成功内容的普通解析仍直接跳过；客户端失败核验仍只标记 repairable。处理器具备补齐能力，但还没有从这两个入口触发独立媒体处理，也没有对生产数据执行批量修复。
2. **客户端缓存身份。** 资产图片仍使用包含短期签名的 Image.network URL；签名更新会改变缓存身份。需要结合内容版本和账号隔离收敛，尚未修改或进行真机命中率验收。

## 验证

使用真实 Pillow、临时文件系统和资产数据库，数据迁移在独立 SQLite 中通过实际 Alembic upgrade 验证；网络仅替换边界：验证写失败不发布引用、同键并发原子写、缺文件恢复、缩略图本地重建、签名 URL 保真、部分归档不丢媒体，以及变体元数据与实际文件一致。

临时压缩验收：一张仓库 JPEG 样本 43,852 B → 25,164 B，缩略图 3,920 B；合成噪声 PNG 2,218,426 B → 458,840 B。另一个 JPEG 转码未节省空间，因此保留单份源图；110 B 的小 PNG 不增加缩略图。仅代表这些样本，不推断全库节省比例。临时脚本验收后删除。
