# 产品导航与自动化体验设计

> 日期：2026-06-05  
> 目标：为 VaultStream 后续功能扩展、收藏夹同步、账号管理、Agent/RAG、时间线和无人值守自动化建立统一的信息架构。

## 总体判断

当前底边栏更像“功能模块列表”，而不是“用户任务结构”。统计、收藏库、探索库、推送、设置这 5 个入口在当前阶段还能工作，但继续加入 Agent、RAG、同步进度、时间线、自动浏览后会快速膨胀。

未来不应再沿用“新增功能 = 新增底边项”的模式。VaultStream 的产品方向应从“收藏工具 + 若干附加功能”收敛为：

> 个人内容摄取、理解、归档、自动分发系统。

主导航应该围绕用户每天如何处理信息，而不是围绕后端模块名。

## 推荐主导航

未来主导航建议收敛为 4 个核心入口：

1. 动态 / Home
2. 收藏库 / Library
3. 收件箱 / Inbox
4. 自动化 / Automation

设置不再占用主导航。Agent 和 RAG 不默认作为独立底边项。

当前落地：

- 移动端底边栏和桌面侧边栏已收敛为 4 项：动态、收藏库、收件箱、自动化。
- 原 `Dashboard` 已在 UI 中重命名为“动态”，`Discover` 重命名为“收件箱”，`Review` 重命名为“自动化”。
- Settings、Agent、账号中心不再作为主导航项；移动端在“动态”页通过“辅助入口”打开，桌面端通过侧边栏辅助按钮打开。
- 路由保留兼容：`/dashboard` 重定向到 `/home`，`/discovery` 重定向到 `/inbox`，`/review` 重定向到 `/automation`。

### 1. 动态 / Home

动态页取代当前“统计”作为第一入口，但它不应该只是统计页改名。

它的职责是回答：

- 今天系统做了什么？
- 哪些任务失败了？
- 哪些内容待处理？
- 哪些同步刚完成？
- 哪些推送待审核？
- 自动化系统下一步会做什么？

适合放入动态页的内容：

- 今日新增内容。
- 最近同步运行结果。
- 失败任务提醒。
- 待审核分发队列摘要。
- 待分拣收件箱摘要。
- 平台账号异常提醒。
- 远期时间线。

当前首版已在动态页顶部落地“待处理动态”摘要：聚合解析积压、失败异常、待分发、收件箱候选和最近后台运行，并能跳转到收藏库、收件箱或自动化继续处理。它解决了原统计页首屏只展示数量、无法告诉用户“现在该处理什么”的问题。

统计只作为动态页中的局部概览，不再作为独立主入口。

### 2. 收藏库 / Library

收藏库是用户沉淀内容的地方，是 VaultStream 的核心资产入口。

职责：

- 浏览已收藏内容。
- 搜索、筛选、标签、平台视图。
- 语义搜索。
- RAG 问答。
- 内容洞察。
- 内容详情和后处理状态。

RAG 不应优先做成独立底边项。它更适合作为收藏库里的高级搜索和问答模式：

- 搜索框支持关键词 / 语义 / 问答模式。
- 用户可限定范围：全部收藏、某标签、某平台、某时间段、选中内容。
- 回答应能回链到内容和片段。

统计页中的平台分布、标签分布、内容趋势、索引状态等，可以迁移为收藏库中的“洞察”弹层、侧栏或顶部按钮。

### 3. 收件箱 / Inbox

当前“探索库”应扩展为更广义的收件箱。

收件箱的职责是承接所有尚未成为长期收藏资产的内容：

- RSS 和 Telegram 发现内容。
- 账号收藏同步导入候选。
- 自动浏览发现内容。
- Agent 推荐内容。
- 解析失败待修复内容。
- 低置信度、待人工确认的内容。

核心动作：

- 收藏。
- 忽略。
- 稍后处理。
- 加入规则。
- 分发。
- 修复失败。
- 批量处理。

探索不应只是“发现源列表”，而应成为系统所有输入源进入用户决策前的缓冲区。

### 4. 自动化 / Automation

自动化页应合并当前推送、收藏夹同步、账号管理、平台健康、分发规则和任务进度。

它回答：

- 从哪里来？
- 怎么筛选？
- 同步是否正常？
- 解析是否正常？
- 到哪里去？
- 失败后怎么办？

适合放入自动化页的模块：

- 账号中心。
- 收藏同步。
- 发现源配置。
- 分发规则。
- 推送目标。
- 后台任务运行记录。
- 平台健康。
- 自动化日志。

“推送”不应再单独作为主导航项。推送是自动化流水线的输出端，应并入自动化。

## 设置入口

设置是低频维护入口，不应继续和收藏库、收件箱、自动化同级。

建议：

- 桌面端：左下角头像/齿轮入口。
- 移动端：动态页右上角齿轮，或自动化页内的系统设置入口。
- 设置内部保留高级配置：本地连接、API token、主题、模型 provider、存储、调试等。

普通用户不应先面对底层模型字段。AI 配置应优先展示能力状态：

- 内容理解：可用 / 不可用。
- 摘要生成：可用 / 不可用。
- 语义搜索：可用 / 不可用。
- Agent：可用 / 不可用。

高级设置再展示 provider、base URL、model、API key、embedding dimension 等。

## 收藏夹同步设计

收藏夹同步不要继续藏在设置页里。它应属于“自动化 + 账号健康”的一部分。

### 账号中心

当前首版已经通过 `/accounts` 独立页面落地，但不加入底边栏，避免扩大主导航负担。
页面已聚合平台健康、登录检测、扫码/重新连接、收藏同步预览和最近收藏同步任务。
下列能力仍是后续增强方向。

账号中心按平台展示：

- 知乎。
- 小红书。
- Twitter / X。
- Bilibili。
- 微博。
- 其他未来平台。

每个平台卡片显示：

- 登录状态。
- Cookie 状态。
- 最近验证时间。
- 最近同步时间。
- 最近失败原因。
- 可用能力：解析、收藏同步、用户主页、搜索等。

操作：

- 登录。
- 刷新 Cookie。
- 登出。
- 测试解析。
- 测试收藏同步。
- 查看失败历史。

### 同步配置

每个平台应支持：

- 是否启用自动同步。
- 同步频率。
- 同步范围。
- 首次同步策略。
- 重复内容策略。
- 取消收藏后的处理策略。
- 失败重试策略。

同步范围应逐步支持：

- 全部收藏。
- 指定收藏夹/分组。
- 最近 N 天。
- 仅未导入。
- 指定关键词或标签。

### 同步运行记录

每次同步应产生可追踪 run：

- run id。
- 平台。
- 触发来源：自动 / 手动 / Agent。
- 开始时间。
- 结束时间。
- 扫描数量。
- 导入数量。
- 重复数量。
- 失败数量。
- 失败原因摘要。
- 可重试项。

前端触发同步后不应只收到 202 accepted。应该能跳转到运行记录，看到任务结果。

当前首版已支持从动态页后台运行时间线携带收藏同步 `run_id` 跳转到自动化页收藏同步标签，并自动打开匹配 run 的结构化结果摘要。导入阶段的单条失败会保留最多 5 条失败样本，前端可展示失败 URL、标题和错误。后续仍需要把这类结果详情扩展为可分享、可刷新、可按失败项重试的独立结果页。

## 统计页处理

当前统计页内容较丰富，但使用频率低，不适合作为主导航入口。

建议移除“统计”底边项，并拆解到上下文中：

- 动态页：今日新增、失败任务、待审核、最近推送。
- 收藏库：内容数量、平台分布、标签分布、索引状态。
- 自动化：同步成功率、推送成功率、失败趋势。
- 收件箱：来源质量、AI 评分分布、忽略率。

统计应变成“上下文洞察”，而不是独立页面。

## Agent 与 RAG 入口

Agent 不应默认成为底边栏孤岛。

推荐方式：

- 全局保留 Agent 按钮或命令面板。
- 在收藏库中，Agent 用于“问这些内容”“整理标签”“找相似内容”。
- 在收件箱中，Agent 用于“帮我筛选”“批量总结”“解释为什么推荐”。
- 在自动化中，Agent 用于“创建规则”“诊断失败”“优化同步配置”。

RAG 也不应孤立成一个页面。它应是收藏库和时间线上的高级搜索/问答能力。

只有当 Agent/RAG 的使用频率超过收藏库和收件箱本身，才考虑独立主导航入口。

## 远期无人值守系统

远期目标是“自动浏览与推送系统”。核心不是新增更多页面，而是让用户看懂整条流水线：

> 来源 → 收件箱 → 理解/评分 → 收藏库 → 分发 → 反馈

用户需要知道：

- 哪些来源在工作？
- 今天抓到了什么？
- AI 为什么保留或忽略？
- 哪些内容进入收藏库？
- 哪些内容被推送？
- 哪些失败了？
- 系统下一次会怎么做？

因此动态页和自动化页非常关键：

- 动态页展示系统运行和用户待处理事项。
- 自动化页控制规则、账号、同步、分发和失败恢复。

## 建议迁移路线

### Phase 1：信息架构重命名与入口收敛

- 已落地：统计改为动态页。
- 已落地：探索改为收件箱。
- 已落地：推送/审核入口并入自动化。
- 已落地：设置和 Agent 从底边栏/侧边主导航移出。
- 已落地：主导航收敛为：动态、收藏库、收件箱、自动化。

仍需继续：

- 自动化页已新增收藏同步标签，可查看平台状态、最近同步 run、预览同步、触发同步并重试失败 run。
- 自动化页已新增健康矩阵，聚合平台账号、发现源和推送目标的异常状态，并提供登录检测、发现源同步、推送目标刷新、账号中心、发现源/推送设置和动态页入口；平台账号行已可从最近收藏同步 run 跳转到对应结果摘要；自动化页和设置页已支持 Tab 级深链接，可从异常项附近直达健康矩阵、AI 发现配置或推送配置。但深度健康测试、完整行级日志跳转和更完整后台运行记录仍未完全合并。
- 动态页已新增首版待处理动态摘要和运行时间线，可查看单次后台 run 的详情抽屉，并从详情进入收藏同步、分发历史、收件箱或收藏库；收藏同步 run 已能携带 Run ID 进入自动化页并自动打开对应结果摘要。但动态页仍保留较多统计页结构，后续需要继续演化为更完整的事件流、失败恢复入口和跨链路待办中心。
- 收件箱当前仍以发现内容为主，尚未承接收藏同步候选、解析失败修复和 Agent 推荐。

### Phase 2：收藏同步产品化

- 账号中心首版已落地；自动化健康矩阵已接入平台账号、发现源和推送目标状态，并具备首批主动操作、配置/动态入口、Tab 级深链接和平台最近收藏同步结果入口。继续增强解析测试、推送目标深度健康测试、失败历史和更细的日志跳转。
- 同步运行记录已有首版，并能在自动化页内查看结构化结果摘要；动态页收藏同步 run 可跨页跳转并自动打开匹配结果，导入失败时能看到失败样本。继续补齐独立结果页和按失败项重试。
- 已落地：收藏同步进入自动化页，支持状态总览、平台状态、预览、手动同步、最近 run、结构化 run 结果摘要、失败样本展示、失败 run 重试和当前策略展示。
- 同步结果进入收件箱或动态页。

仍需继续：

- 自动化页已展示当前真实同步策略：已启用平台范围、按平台 cursor 增量拉取、单轮上限/间隔、重复跳过、不因远端取消收藏自动删除本地收藏、run 级失败重试。
- 收藏夹/分组范围、首次同步策略、重复内容策略配置、取消收藏后的处理策略配置仍未产品化。
- 失败样本已有首版诊断展示，但恢复动作仍以 run 级重试为主，尚未细化到单条失败收藏候选重试。
- 自动化页已可直接调整收藏同步间隔和单轮上限；Settings 仍保留平台速率等更底层的高级配置。

### Phase 3：统计拆解

- 已落地：动态页顶部新增待处理动态摘要，聚合后台异常、解析积压、待分发、收件箱候选和最近后台运行。
- 已落地：动态页新增首版运行时间线，展示最近后台 run，支持详情抽屉，并根据任务类型跳转到相关工作区；收藏同步 run 会携带 Run ID 跳转并聚焦对应结果。
- 继续把原统计页内容拆到动态、收藏库、自动化、收件箱。
- 继续弱化独立统计页结构。
- 保留必要的系统健康摘要。

### Phase 4：Agent/RAG 融入工作流

- 收藏库搜索升级为关键词 / 语义 / 问答。
- 收件箱支持 Agent 辅助批量处理。
- 自动化支持 Agent 创建规则和诊断失败。
- 全局命令面板承接跨页面 Agent 操作。

### Phase 5：时间线与无人值守反馈

- 动态页演化为时间线。
- 展示来源事件、同步事件、解析事件、分发事件、失败事件。
- 自动化根据反馈调整规则和优先级。

## 设计原则

- 不再把每个新能力都做成底边项。
- 主导航只承载高频任务，不承载低频设置。
- 自动化必须可观察、可解释、可恢复。
- RAG 和 Agent 应嵌入具体工作流，而不是孤立聊天页。
- 统计服务于上下文判断，不应独立占据主入口。
- 账号、同步、发现、分发必须共享任务运行记录模型。
