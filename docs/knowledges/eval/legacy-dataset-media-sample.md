# 旧数据库与媒体代表性样本

## 文档状态

active

## 适用范围

- 数据目录：`backend/data_eval/`
- 场景：本地界面、媒体存档和 RAG 回归验证
- 数据快照：2026-07-16

## 背景

`vaultstream.db` 原本对应一份较大的真实抓取数据集。数据库本体约 46.8 MB，但配套媒体包含 21,300 个 WebP 文件，约 1.77 GB，不适合长期作为默认开发数据。

原数据的类型字段不足以直接用于抽样：3,851 条内容中，3,847 条被统一标为 `article`，且绝大部分来自同一批通用网页资讯。因此本次没有按这个粗粒度标签随机删除，而是根据实际阅读和界面测试需要进行分层抽样。

## 抽样原则

基础样本由以下两个维度交叉组成，每个有效组合保留时间顺序上的前部、中部和后部代表：

- 正文长度：短文、中等正文、长文、超长正文。
- 媒体形态：无图、单图、2 至 4 图、5 至 10 图、10 图以上大图集。

另外强制保留：

- Zhihu 空内容异常样本。
- 两个 `webpage` 内容样本。
- 一个 Bilibili 动态及作者头像、富媒体元数据样本。
- 最大图集和最长正文样本。
- 现有 RAG ground truth 使用的内容 `71`、`179`、`199`、`906`、`1630`。

最终保留 57 条内容、405 个去重媒体对象。内容 ID 为：

```text

201, 218, 356, 425, 562, 589, 906, 1548, 1630, 1654, 1756, 1759,

2299, 2321, 3421, 3544, 3691, 3699, 3700, 3737, 3777, 3786, 3798,

```

## 当前文件角色

- `backend/data_eval/vaultstream.db`：默认精简样本库，共 57 条内容；其本地媒体引用全部可用。
- `backend/data_eval/media/`：精简样本媒体。405 份原图和 405 份缩略图，共 810 个文件、48,105,598 字节。

原始完整数据库备份在样本完整性和 RAG 回归验证通过后已删除，避免形成无人维护的第二事实源。若未来确实需要扩大样本，应从可追溯来源重新采集并按新的模板覆盖需求增补，而不是恢复旧全量副本。

## 清理结果

- 删除全量媒体副本和代理缓存：21,300 个文件、1,767,666,436 字节。
- 保留代表性媒体：810 个文件、48,105,598 字节。
- 相比原媒体副本减少约 1.72 GB。
- 删除原始完整数据库备份和一次性评估报告，仅保留可重复生成报告所需的脚本、基准与代表性样本。
- `proxy_cache` 不属于稳定存档证据，未纳入样本。

## 验证结果

- 精简数据库 `PRAGMA integrity_check`：`ok`。
- 精简数据库内容数和 FTS 行数：均为 57。
- 405 个本地媒体引用均存在原图和缩略图，缺失文件数为 0。
- 现有 5 条 RAG ground truth 在精简库中 `Recall@5 = 1.0`、`Recall@10 = 1.0`。

## 已知限制

- 这份数据仍以图文资讯为主，不能代表未来的视频、音频、帖子串、消息包和文档模板。
- 抽样目标是保留回归与界面测试价值，不是构建统计学无偏数据集。
- 后续引入新的存档模板时，应另行加入少量人工确认的黄金样本，不应再次导入大规模媒体抓取副本。
