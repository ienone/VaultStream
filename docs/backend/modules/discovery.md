# 后端模块：发现与候选信息流

## 文档状态

active

## 代码位置

## 功能

- 同步发现源。
- 存储候选内容和状态。
- 支持候选内容进入收藏库或被忽略。
- 可选进行 AI 巡逻评分。

## 不承担职责

- 不管理正式收藏内容的长期编辑。
- 不直接配置平台账号登录。
- 不直接执行分发推送。

## 实现逻辑

发现源同步把外部来源内容写入 discovery/contents 相关状态字段，并用 `ContentDiscoveryLink` 保留一个内容与多个发现源的关系。候选列表返回来源正文预览、全部关联来源名称和类型；预览只是来源材料，不伪装成 AI 摘要。巡逻评分根据兴趣配置对候选项赋分，并决定是否可见或忽略。

单条候选动作支持收录、忽略、稍后处理和恢复为可见。`snoozed` 是独立持久状态，默认动态流不返回，只有稍后列表显式请求该状态；恢复是明确的 `visible` 状态转换，不通过本地假恢复掩盖后端状态。批量动作复用同一状态机。

发现源质量测试返回具名诊断 contract；前端 provider 将 `run_id/status/ok/elapsed_ms` 与候选统计解析为 typed result，页面不再直接读取动态 map。来源同步、删除和候选批量动作也已有命名响应并进入 OpenAPI 门禁。

## 配置与策略

- 等待评分的 `ingested` 候选同样遵守 TTL。巡逻只读取未删除且未过期的候选，每批最多 100 条；模型调用或输出失败后结束本批，避免配置错误时逐条重复请求。编辑竞态只跳过对应候选。
- 每六小时清理后回收无引用的内容寻址媒体，核对内容引用、归档元数据及资产变体，保留共享文件和软删除内容引用；最近 24 小时写入的文件暂缓回收，下一轮再检查。

- 发现源 `enabled` 应约束定时同步、手动同步和 Agent 工具入口。
- 巡逻评分、清理策略和同步间隔来自系统设置。
- 候选 TTL 的严格边界为 `expire_at < now`。`expire_only`、`archive`、`hard_delete` 共用同一资格规则：只处理未采纳且无持久依赖的 `visible`/`expired`/`ignored` 候选。
- 任一知识事件成员（包括已归档事件及所有成员角色）、用户显式分享或收藏导入产生的 `ContentSource`、分发队列或已发送记录、真实父子内容关系都会阻止自动 TTL 清理。受保护候选保留原状态、正文、来源、搜索索引和关联；保护不等于自动提升为 `promoted`。
- SQLite 清理在短写事务取得 writer lock 后再检查资格并执行状态变更、归档或删除，避免事件加入、显式保存和分发引用在“先查后删”窗口中丢失。用户主动擦除不走此自动 TTL 规则。

## 尚未实现 / 计划扩展

候选浏览、收录、忽略、稍后处理、恢复和两个列表的分页读取已经进入动态信息流，不恢复独立收件箱。事件变化、来源偏好和更完整的主动探索仍待后续功能切片。

RSS/Atom 抓取失败会向同步任务与来源测试传播错误，不再以空条目伪装成功；HTTP 状态错误仅报告状态码，连接/解析错误使用固定诊断，不记录带凭据的订阅 URL 或响应正文。有效空订阅正常返回，错误不推进游标。

Telegram 公开频道同样检查 HTTP 与公开消息页结构，失败传播到运行账本且保留游标；固定诊断不包含订阅 URL 或上游正文。首次读取最新公开页（最多 20 条），后续按保存的频道/消息编号沿 `data-before` 向历史翻页，直到跨过已保存编号，避免只读最新 15 条丢失停机期间消息。原游标消息被删除仍可根据数值边界续接。单轮最多 100 页，超限或分页无进展明确失败而不推进游标。此路径只支持 `https://t.me/频道名` 或 `/s/频道名` 的公开网页，不代替 Bot 接收、私有频道账号 API 或全历史导入。

巡逻评分要求有限的0–10数值及严格的 reason/tags 字段类型，拒绝布尔值、越界分数和NaN/Infinity；非法输出不修改候选。自动批次存在失败时记录 error 及成功/失败数量，成功项保留、失败项仍待处理，不再把全部失败记成成功。

巡逻评分提交以读取时的 Content.updated_at 为条件；模型等待期间正文或候选状态改变时不提交迟到结果。手动接口返回409，自动批次计为未成功且继续其他候选。每条成功评分独立提交，下一条模型等待前释放写锁；版本冲突的空写事务同样立即结束。

巡逻仅写评分、理由、AI标签和候选状态，不生成或覆盖内容摘要；原摘要、原文、语义切片和索引保留。摘要由独立摘要服务及其自动开关管理，关闭自动摘要后巡逻不会绕过开关产生摘要。

## Telegram 视频与发现媒体

Telegram 公开消息读取网页 video.tgme_widget_message_video 的真实 src，播放器背景图仅作封面。DiscoveryItem 显式传递 layout_type 和 archive_metadata，入库保留视频布局及 images/videos 分类；不根据视频地址伪造图片封面。

发现媒体归档按既有总开关、图片开关、视频开关及数量/大小限制执行。图片与视频分别交给现有处理器；只替换成功归档的地址，保留未归档媒体，避免图片归档后丢失同一消息的视频。RSS 未分类的媒体仍按其图片 contract 处理。

## Telegram 原生账号来源

开启账号频道同步后，每五分钟枚举已加入频道，有效通知开启且来源 enabled 的频道进入原生同步。MTProto 来源配置标记 transport=mtproto，公共 HTML 调度不再重复处理；单来源手动同步转到账号任务。原生消息出现记录与候选归属分别持久化，同载荷转发复用正文和已下载媒体。新候选仍走现有保留期与兴趣评分；关闭或静音不删除已收录内容。原生来源的质量预览尚未接入。
